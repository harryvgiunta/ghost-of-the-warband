# New humanoid characters and their animations

Use this route for a new player/NPC humanoid, a replacement Ranger, a new outfit, or a humanoid animation set. Use [wolf authoring](wolf-authoring.md) for quadrupeds; do not apply either anatomy map blindly to the other. Read [Ironwood Assets](../../ironwood-assets/SKILL.md) for source licensing, topology/UV/PBR production and packaging, and [Ironwood Archer](../../ironwood-archer/SKILL.md) for current player combat/animation contracts.

## 1. Choose compatibility before building

**Input:** the requested character, role (player or NPC), visual references, target height/proportions, required equipment/actions, and actual runtime consumer.

1. Inspect `scripts/archer.gd`, `assets/characters/ironwood_ranger.json`, the GLB and `tools/prepare_character.py` for a player replacement. The current Ranger has a 65-bone skeleton, a Godot-imported +Z visual forward converted to gameplay -Z, measured palms, a cheek bow anchor and sword socket. These are facts about that asset, not universal humanoid defaults.
2. Choose the smallest compatible route:
   - **Outfit/appearance only:** preserve the existing skeleton/rest transforms and action library; replace/reweight the requested mesh/material surfaces and revalidate motion clearance.
   - **New body proportions on compatible skeleton:** measure new rest transforms, re-skin, retarget/rebake the selected motions and remeasure all hand/face/foot/socket landmarks. Same bone names do not imply the same reach.
   - **New independent rig/NPC:** define its own skeleton/animation metadata and actual controller contract. Reuse the pipeline, not the Ranger's hardcoded bone indices or player actions by assumption.
3. A new name/file is not a runtime integration. Identify whether the character is loaded through the existing `CHARACTER` preload, a new scene, or an NPC construction site. Update all consumers deliberately; do not create a second unused model while claiming replacement.
4. Preserve gameplay balance, weapon sizes, attack gates, collision and networking unless the request changes them. A different apparent height does not automatically authorize new damage/reach/speed. Record conflicts between the requested anatomy and existing collision/weapon reach rather than hiding them in bone scaling.

**Gate:** a concrete compatibility choice, required clip list, measured target dimensions and bounded integration files. No asset authoring before deciding whether old clips/sockets must remain compatible.

## 2. Model, UV and skin the character

1. Block the silhouette against front/side references: rib cage, pelvis, spine curves, shoulder breadth, neck/head, arm/leg proportions and hand/foot sizes. A stylized character still needs joints capable of the requested motions. Keep feet on a defined sole plane and a measured ground origin.
2. Build continuous deforming skin with loops around shoulder/armpit, elbow, wrist, hip/groin, knee, ankle, neck and jaw. Give each bend room on both sides. Avoid long thin faces across the groin or welded shoulder/torso surfaces that collapse when arms lift.
3. Model clothing with appropriate clearance for crouch, full overhead reach, bow draw, running and roll—not only the rest pose. Remove body surfaces hidden permanently by opaque clothing when that does not create gaps during motion. Keep movable accessories attached to real bones/sockets; don't leave eyes, teeth, hair or armor behind when the head/torso moves.
4. UV and author portable base-color/normal/roughness/metallic textures using the asset skill. Keep skin, cloth, leather, metal, hair and eyes materially distinct. A global tint cannot replace a proper painted character or a clothing material set. Preserve editable masks if future color variants are relevant.
5. Apply mesh/armature object transforms before binding. For an already bound imported asset, preserve and deliberately convert its bind matrices rather than applying transforms destructively. Keep positive uniform scales and record exported units/axes.
6. Use a root/pelvis/spine/chest/neck/head hierarchy, clavicles and upper/lower arm/hand chains, thigh/calf/foot/toe chains, and enough fingers to grip required equipment. Add face/jaw/eyes only as needed. A source-compatible rig can retain its actual names; a new rig needs an explicit semantic bone map, not guesses such as treating every `Head` origin as the jaw.
7. Assign deform-bone vertex groups, normalize weights, remove unweighted vertices, and start with at most four effective influences per vertex. Blend shoulders/clavicles, hips and wrists through appropriate loops. Rigid objects such as teeth/eyes attach to the correct head/jaw region. Inspect after influence pruning; a low influence count is not proof of good deformation.
8. Test shoulder elevation, elbow flexion, wrist roll, deep hip/knee bends, spine twist, head turn and finger closure on the actual skinned mesh. Fix collapsed volume and clothing intersections in topology/weights/rest placement before baking a full library.

**Gate:** exported-and-reimported neutral rig and extreme-pose renders with attached parts, correct joint bends, fixed bone lengths, correct axes and readable PBR surfaces.

## 3. Author or retarget actual humanoid clips

1. Inventory the source's actions, frame rate, frame ranges, rest matrices, action slots and licensing. Use only real source clips or genuinely authored Blender keys. Do not claim a paid/non-downloaded library is available. The Ranger provenance records actual selected Quaternius and Gres sources; use their exact input requirements only if rebuilding that pipeline.
2. Define the required set from the controller. A new walking NPC does not need all player combat clips. A player replacement must support every live action: idle, walk/jog/sprint, jump start/loop/land, roll, required sword carry/overhead and bow overlay compatibility. Read actual names from metadata and `AnimationPlayer`, not filenames or a list copied from another asset.
3. Retarget source motion using source/target rest-frame conversion and quaternions, preserving hierarchy and anatomical bend direction. Treat planar root translation, vertical pelvis motion and joint rotations separately. Convert root motion to the controller's in-place policy and record nominal stride travel. Matching names are not a valid retarget algorithm.
4. If creating motion, key contact and weight-transfer landmarks: heel/toe contact, stance support, toe-off, swing, pelvis shift, counter-rotating torso, purposeful arms/head. Bake evaluated deform-bone transforms at 60 Hz. For attack clips, key anticipation, loaded pose, fast contact interval, follow-through and recovery. A random arm arc or rigid-body rotation labeled “attack” is not the deliverable.
5. Preserve source movement meaning. Do not relabel a horizontal slash as an overhead cut, use a one-hand clip for a heavy two-hand strike, or substitute a tumble with a translated standing character. If source timing needs cleanup, retain the ordered trajectory and retime anticipation/recovery rather than erase its striking interval.
6. For the current player, read the Ranger JSON attack source landmarks and the live `Archer`/`Combat` phase logic. Preserve the bow's 1/2/3-second charge, release/re-nock phases, partial-charge damage, independent sword recovery, continuous real blade sweeps and roll gating. Visual pose/weapon sockets must drive the same contact samples used by combat; do not introduce a duplicate damage event in a clip.
7. Remeasure weapon and face contacts from the finished character: actual palm surface, cheek anchor, hand-local grip orientation, foot sole offsets and equipment clearances. The Ranger's `Head` joint is near the neck base; blindly using it as the jaw would place the drawing hand incorrectly. Sword orientation comes from the actual grip/socket, not a guessed hand Euler axis.
8. For two-hand equipment, keep the primary authored striking arm and correct the support palm with a stable anatomical bend plane and feasible clavicle reach. Do not stretch bones or freeze a carry frame while the torso animates. Check the actual skinned torso/clothing through windup and recovery; endpoint coordinates alone can hide arm intersections.
9. Bake constraints/IK into export bones, preserve deliberate clip names and endpoint/loop derivatives, remove unrelated actions/control objects, and export using the verified GLB API. Blender 5.x actions may require an assigned action slot; inspect `set_action()` in the existing preparation tool and the installed API. A constraint/control rig that did not export is not runtime animation.

**Gate:** measured exported clips with matching contact/impact landmarks, complete action coverage for the selected controller, no root drift, no foot sliding, stable arms/weapon contact and genuine authored whole-body motion.

## 4. Integrate with one pose writer and validate

- Use one animation evaluator per character, with explicit physics/manual clock ownership. Keep gameplay root movement separate from the visual-axis conversion and any intentional visual scale. Drive cadence from achieved post-collision movement, not requested speed.
- Blend/cache authored poses before adding crouch, terrain or weapon IK. Never cache the visible corrected skeleton as the next authored base: repeated transitions can add the same pelvis/hand/terrain offset again. Rotation-only nodes construct intended unit rotations; do not repeatedly preserve numerical scale drift through Euler setters.
- Update skeleton paths, semantic bone mapping, sockets/metadata and every runtime caller together. Missing required bones/clips must fail clearly rather than silently substitute an unrelated animation or primitive model. Leave unrelated characters and scene behavior unchanged.
- If the change affects the shared player rig, migrate both Frontier and Arena, including `get_animation_state()`/`apply_animation_state()` and authoritative actor snapshots. Clients submit input, not trusted animation/damage claims. An independent single-player NPC is not automatically an arena feature.
- After integration, follow the project skill's existing behavior regressions and exercise the real changed character in game. Inspect front/side/back and opposing stride phases, aim/draw/partial release/re-nock, one- and two-hand strike/recovery, jump/roll, crouch/peek, slopes, equipment swaps and repeated transition cycles as applicable. Keep before/after evidence of a specific deformation repair.
- Existing `tools/character_clearance.py` and arm-clearance regression are tailored to the Ranger mesh/bone conventions. If changing anatomy, adapt their real measured inputs or create relevant deterministic geometry checks; do not claim an unchanged humanoid test validates a new mesh without inspection.
- Deliver source/provenance, actual runtime model/materials/clips, measured metadata, importer settings and a working rebuild command using implemented scripts. See [variants and evidence](variants-and-evidence.md#delivery-and-evidence) for the handoff structure; replace wolf-specific timing checks with the actual humanoid controller contracts.

For a new body/animation task, keep requested appearance work separate from unrelated gameplay tuning. Completion requires the visible, textured, animated character in its actual consumer—not only a generated file or a neutral skeleton preview.
