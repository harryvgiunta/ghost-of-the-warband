# Ironwood Archer

Work from the repository root containing `project.godot`. Paths below are repository-relative, not relative to this skill directory. Treat the current code and the user's requested behavior as authoritative; this skill records the existing contracts, not a prohibition on intentional changes.

## Orient before editing

1. Read the relevant portions of `README.md` and locate the affected symbols and callers. Preserve existing GDScript, signal, and scene conventions.
2. Separate shared gameplay from controller-specific input. A frontier-only fix is incomplete when the same feature is available in the arena.
3. Inspect the current launcher and setup files before changing the engine version or executable paths. Use the managed engine or the user's `GODOT_PATH`; do not introduce a new toolchain.
4. Check whether a GDScript language server is available before symbol navigation/refactors. If unavailable, use scoped symbol searches and Godot's parser/runtime; do not claim LSP verification.

## Gameplay contracts to preserve

### Main menu, town and in-world state

- `project.godot` sets `run/main_scene="res://title.tscn"`; every normal launch opens the **main menu**: **Start New Game**, **Load Saved Game**, **Host Open World**, **Join Game**. `Play.cmd` therefore opens the title screen. `Host World.cmd` launches `main.tscn` with `--world-host --world-port 7777 --world-name "%USERNAME%"`; `Arena.cmd` opens `arena.tscn` directly for the standalone lobby. `menu.tscn`, `menu.gd`, `menu_hud.gd` and `field_inventory.gd` are deleted; do not reintroduce an out-of-game depot.
- **Start New Game** calls `PlayerState.reset(true)` and loads `main.tscn`; the ranger spawns at `world.player_spawn == town_entry`, the south gate `(0,3,47)`, facing into Hearthstead. **Load Saved Game** calls `PlayerState.load_state()` and also loads `main.tscn`; it is disabled when `state.save_path` does not exist. **Host Open World** arms `Session.arm_world("world-host",...)` on the remembered/`--world-port` port, remembers `NetCache.mode == "world"`, prints `IRONWOOD_HOST_WORLD port=`, and loads `main.tscn` **without** resetting or reloading `PlayerState`. **Join Game** validates name/address/port, offers **Arena match**, **Delve party** or **Open world**, remembers name/address/port/mode in `NetCache`, arms `Session.arm_arena("client",...)`, `Session.arm_delve("delve-join",...)` or `Session.arm_world("world-join",...)`, and loads the matching scene.
- The town is built by `range_world.gd._build_village`: **Smith Brann** in `ForesterHouse` (`vendor` 1), **Storekeeper Orla** in `FletcherWorkshop` (`vendor` 0), **Quartermaster Vey** in `HearthsteadStore` (`vendor` 2), the **Town Stash** chest under the market awning, the **Arena Portal** at `(7,3,44)`, the **campfire**, and the **delve hatch**. Each keeper has a counter and a placeholder humanoid, and its interactable point is on the customer side. `main.gd` dispatches `kind == "vendor"`/`"stash"`/`"portal"`/`"camp"`/`"waystone"`; the `kind == "delve"` entry is a map marker only and must be skipped by the prompt loop.
- The delve hatch is a **physical hole**: `_build_terrain` skips the cell `ix=80, iz=93` (world x 15..17, z 41..43) from the shared visual/collision mesh, and the hatch root sits at world `(16,3.06,42)`. `main.gd._physics_process` calls `world.is_over_delve_hatch(player.global_position)` and, below `y < 2.25`, calls `_enter_delve()`. Never replace this with a G prompt. The shaft walls and dark bottom are visual/solid support; the inn interior must stay reachable.
- `PlayerState` is the only authority for gear. `INVENTORY_CAPACITY` is **15** and `STASH_CAPACITY` is **20**; both are hard limits enforced by `buy`, `move_to_stash`, `move_to_inventory`, `try_pickup` and `pickup_floor`. `equipped` is a separate ten-key dictionary, `quick` holds the bound TAB pair, and `floor_items` has no capacity limit. World drops leave the pack through `take_from_inventory(index)` and `take_equipped(slot)`: both commit the removal and return `{ok,item_id,message}` but never append to `floor_items`, because the scene spawns the pickup instead.
- The starting state is the five Ranger leather pieces plus the shortbow equipped (`main="bow_short"`, empty `off`), and **all twelve catalog weapons** in the backpack: `STARTING_INVENTORY = ["bow_short","bow_recurve","bow_long","sword_short","sword_arming","sword_great","dagger_iron","staff_fire","staff_bone","shield_buckler","shield_kite","shield_tower"]`, an empty stash and floor, and 200 credits. The duplicate shortbow is the equipped bow's spare. Equipped gear is not in the backpack.
- `scripts/world_ui.gd` is the only in-world kit. `configure(state, session, rig, drop_handler, town)` builds it; `open_inventory()`, `open_equipment()`, `open_stash()` and `open_vendor(index)` set the visible view; `active_view()` returns `"inventory"`, `"equipment"`, `"stash"`, `"vendor"` or `""`; `close()` hides it; signals are `opened`, `closed` and `loadout_changed`. **I** opens inventory, **P** opens the equipment paperdoll. The UI owns `PlayerState` mutations (`equip_from_inventory`, `unequip_to_backpack`, `move_to_stash`, `move_to_inventory`, `pickup_floor`, `buy`, `sell`, `bind_quick_from_equipped`, `take_*`/`drop_*`) and emits `loadout_changed`; the scene applies `PlayerState.loadout()` to the live rig and owns cursor/movement blocking. It never touches the mouse cursor itself.
- Vendor identities are `PlayerState.VENDORS`: index 0 **Storekeeper Orla** tag `STORE` (5 bows/staves), index 1 **Smith Brann** tag `SMITH` (3 swords + dagger + 3 shields), index 2 **Quartermaster Vey** tag `QUARTERMASTER` (20 armor + 2 foci + 2 necklaces + 3 rings). Selling pays `floor(price * 0.6)`. Bought gear does not auto-equip and needs a free backpack slot.
- Persistence writes `user://player_state.json` on every mutation and loads on autoload ready. Version 4 stores `{version,credits,inventory,stash,equipped,quick,floor}`; `equipped` carries all ten slots directly, `quick` is the bound TAB pair, and `floor` is the dropped-gear list. Version-1, -2 and -3 saves migrate on load; a missing `quick` key restores the default shortsword/buckler bind. Unknown ids and excess backpack/stash entries are dropped; floor entries are filtered by item id. Deleting the file restores the starting kit.
- All game modes start from `PlayerState.loadout()`: `build_loadout(main,off,armor_pieces)` derives `{main,off,weapon,bow,sword,staff,armor,shield,off_weapon,focus}`. The main hand decides bow / sword / dagger / staff / unarmed; the off hand decides shield / focus / second one-hander. Session keys `1`–`5` still change that session's weapon mode but are not written back; only `world_ui` and TAB mutate the persistent kit.
- Quick swap is one bound hand pair, persisted as `quick = {main,off}`. `QUICK_DEFAULT` is shortsword + buckler, matching the equipped starter bow. `quick_swap()` pools the backpack plus both equipped hands, consumes the target pair, stows the outgoing pair and makes the outgoing pair the new bind, so TAB toggles; it never creates or destroys gear and fails when a target is not carried (the stash is not a swap source) or the stowed pair would exceed `INVENTORY_CAPACITY`. `bind_quick_from_equipped()` stores the current legal pair from the paperdoll's **BIND SWAP** action. The frontier applies the new loadout locally; arena and delve reuse `_on_ui_loadout_changed()`/the validated `"loadout"` action, so clients stay host-authoritative.
- Loot rate: `scripts/loot_rules.gd` owns the one knob (`SCALE = 0.1`, `drops()`). Frontier kills roll it for the held weapon (10%) and again for the alternating `LOOT_SEQUENCE` piece (5% overall); delve devil and clone weapon drops roll it (10%); the delve cache rolls it for its item (10%). Gold rewards and waystone payments are not scaled. Keep new drop paths behind `LootRules.drops()` so the rate stays tunable in one place.
- Frontier rewards use `_award_gold`, which updates the visible session gold and calls `PlayerState.add_credits`. Frontier kills also drop physical gear: `main.gd._on_enemy_defeated` asks `Enemy.held_weapon_id()` first and spawns that exact catalog piece when a cinder devil holds a dagger, sword or bow; claw devils, wolves and sentinels keep the alternating `LOOT_SEQUENCE` drop. `scripts/held_weapon.gd` is the shared role-to-item map (`dagger`→`dagger_iron`, `sword`→`sword_short`, `bow`→`bow_recurve`). The corpse releases its weapon mesh on death. Loot enters the backpack only.
- World drops reuse `LootPickup` with the `armed` latch: `main.gd._drop_field_loot` and `delve.gd._drop_field_item` spawn them unarmed at the ranger's feet (the delve drops 0.8 m along the camera facing), and `_collect_loot` arms an unarmed pickup only once it is outside the 1.6 m reach. Keep the arming step. Arena passes no drop handler, so its drops use `drop_equipped`/`drop_from_inventory` and join `floor_items`.
- The arena consumes `Session.take()` once in `_read_arguments`; `--arena-host`/`--arena-join` remain authoritative. The town portal arms `mode="skirmish"`, which calls `host_game(..., find_open_port=true)` and tries 7777 through 7792. The title **Join Game** arms `mode="client"`. Clients register `{main,off,bow,sword,armor}` with `_register`; the host validates catalog ids and the packed armor bits before rebuilding the seat. A client's live `"loadout"` action reuses the same path.
- Return paths: the town HUD's **R** returns to `world.player_spawn`; the arena lobby's **Return to Town** loads `main.tscn`; the delve rope and both delve game-over buttons load `main.tscn`. There is no Hollow.

### Equipment slots and item taxonomy

- `EquipmentRules.SLOTS` is `["head","chest","hands","legs","feet","neck","ring1","ring2","main","off"]`; `SLOT_LABELS` names them Head/Chest/Hands/Legs/Boots/Neck/Ring 1/Ring 2/Main Hand/Off-Hand for the HUD. Keep this order for the paperdoll, `PlayerState.equipped` and `build_loadout`; do not reintroduce a backpack-resident equipped kit.
- Item categories are `1h`, `2h`, `bow`, `staff`, `shield`, `focus`, `armor`, `jewelry` and the migration-only `armor_bundle`. `EquipmentRules.allowed(item, slot)` is the single legality rule: one-handers fit main or off; two-handers, bows and staffs fit main only; shields and foci fit off only; armor fits the slot named by its `slot` key; jewelry fits neck or either ring. `auto_slot` prefers main for one-handers, off for shields/foci, the item's armor slot, neck for necklaces, and fills ring 1 then ring 2 before replacing ring 1.
- `plan_equip` is pure and returns fresh `{ok,message,equipped,inventory,floor}` copies. It removes the source item from the backpack first so a swap can reuse that slot, then displaces any previous occupant. A two-handed/bow/staff main-hand equip displaces the old main and the old off item, clearing `off`. An off-hand equip displaces a two-handed/bow/staff main into the backpack and leaves the main empty, then displaces the old off item. Each displaced item goes to the backpack if there is room, otherwise to `floor_items`.
- `unequip_to_backpack` refuses when the backpack is full. `drop_from_inventory` and `drop_equipped` move a piece to `floor_items`; `pickup_floor` and `equip_from_inventory` require room and never drop. `try_pickup` is world loot and appends to the backpack only, never equipping. `move_equipped`/`plan_move` handles paperdoll-to-paperdoll moves and swaps, requires each piece to be legal in its destination, and refuses any result that leaves a two-handed main with an occupied off hand.
- `build_loadout` is the only bridge to a session: it maps bows to `weapon="bow"`, one/two-handed swords to `weapon="sword"`, daggers to `weapon="dagger"`, staffs to `weapon="sword"` with `sword=2` plus a staff index, an off shield to `shield=true`, an off focus to `{"kind","index"}`, and a second one-hander to `off_weapon`. `Archer.apply_loadout` is presentation only and re-checks every setter: it shows the staff instead of the greatsword while `staff_active`, shows a focus only with a supported one-handed main, sockets the off weapon, and selects the shield variant by id (buckler 0, kite 1, tower 2).
- A staff uses `Archer.STAFF_DATA` lengths (1.75 m ember, 1.60 m bone), the greatsword damage/timing and its own middle-grip reach (`STAFF_REACH` 1.6/1.5 m, mirrored in `PlayerState.ITEM_STATS`); it is two-handed and locks the shield. A focus is held and cosmetic (`focus_item.gd`), with no combat effect. The shield is legal with the dagger or any one-handed sword (`can_equip_shield`: `weapon == "dagger"` or `weapon == "sword" and sword_index <= 1`); bow, greatsword, staff and dual wield exclude it.
- The HUD is read-only: `InventorySlot` carries `{area,index,slot,item}` drag payloads and emits `right_clicked` / `slot_dropped`. Panels are `header_panel`, `purse_panel`, `paperdoll_panel`, `backpack_panel`, `stash_panel`, `vendor_panel` and `action_panel`; slot arrays are `paperdoll_buttons` (10), `backpack_buttons` (10), `stash_buttons` (20), `stock_buttons` (28), `vendor_buttons` (3) and dynamic `floor_buttons`. Right-click equips a backpack item with an empty target, or `"off"` while Alt is held; right-click on the paperdoll unequips, on the stash unstashes, and on the floor picks up. Drops route backpack→paperdoll slot, backpack→stash, backpack→floor, paperdoll→paperdoll, paperdoll→floor, stash→backpack, and floor→backpack. Dropping on the 3D view (`_on_world_dropped`) drops a backpack or paperdoll item at the ranger's feet.

### Armor slots

- Armor is five independently equipped slots: **head, chest, hands, legs, feet**. `ArmorData.SLOTS` owns the order, `SET_IDS` is `leather/mail/plate/cloth`, and the item ids are `armor_<set>_<slot>`. Each item's `kind` is its slot, so an armor equip replaces exactly one slot. A legacy whole-set id (`armor_leather`, `armor_mail`, `armor_plate`) is **migration-only**: it is expanded to five pieces when a v1 save loads and is not equippable from the backpack.
- Guard is additive per piece: mail 3/5/2/3/2% and plate 7/9/4/6/4% for head/chest/hands/legs/feet; leather and cloth contribute zero. `ArmorData.reduction` clamps at 45%. `Archer.armor_reduction()` and both controllers must use it; do not restore a single set-index reduction table.
- The rig's `_build_armor_meshes()` groups the imported leather meshes (`Male_Ranger_Head_Hood`, Body/Belts/Pauldron/Arms, Bracer, Legs, Boots) into slot 0 and the generated `Armor_<Set>_<Slot>` nodes into slots 1..3. `Male_Ranger_Arms` belongs to the leather chest so another chest's sleeves replace the skin arms; every non-leather chest must fully cover the arms. Keep head/eyes/brows outside every group.
- `set_armor_piece(slot,set)` preserves the other four slots; `set_armor_pieces(dict)` and `set_armor(set)` are whole-kit helpers. `armor_bits()`/`set_armor_bits()` use two bits per slot in `ArmorData.SLOTS` order. The network snapshot stores the packed 10-bit value in `armor`; the shield bit is `ArmorData.SHIELD_BIT` (bit 10), never the old bit 2.
- `ArenaActor.snapshot()` also carries a compact `gear` int for the visuals the bow/sword/armor fields cannot express: bit 0 off weapon active, bit 1 off kind sword (0 dagger), bit 2 off index, bit 3 staff active, bit 4 staff index, bits 5–6 focus kind (0 none / 1 tome / 2 skull), bit 7 focus index, bits 8–9 shield variant. `apply_snapshot` applies the off hand before the weapon mode so a replicated dual loadout can enter dual, then restores the staff last; the snapshot plus `gear` stays under the ENet MTU budget (checked by `paperdoll_regression`).
- The in-world paperdoll equips individual armor items from the backpack; the town Quartermaster stock is a scrollable 27-item list (20 armor pieces, 2 foci, 2 necklaces, 3 rings, buffered in 28 stock rows). Session keys still accept per-slot set changes for that match, but the arena's quick-loadout panel is hidden; the paperdoll is the visible equipment surface. Do not reintroduce three whole-set buttons.
- The ranger GLB is authored with the armor: `tools/character_armor.py` builds mail/plate/cloth and leather gloves in the rest skeleton with explicit weights, explicit UVs and embedded 512px base-color/normal textures. `Ranger_Base_Calf` is an always-visible dark hose underlayer so short sabatons never expose an empty shin when mixed with the short leather trousers; it is deliberately outside every slot group. The builder is called from `tools/prepare_character.py` after the animations are baked and before cleanup. Keep `Armor_<Set>_<Slot>` names and the `armor.generated` metadata in `ironwood_ranger.json`; the rig reads that metadata to group meshes.


### Input and rolls

- Space jumps; **Shift + Space rolls immediately** from the ground or during a jump. Repeated unmodified Space presses never roll. There is no double-tap window.
- Movement determines roll direction, then facing is the fallback. Keep the single-roll-per-airborne-cycle restriction, normal world collisions, and attack cancellation; a roll is not invulnerability.
- Both controllers pass `event.shift_pressed`. The arena's `jump` action carries an explicitly validated boolean, not a trusted client animation state.
- `6` uses a bandage and `7` drinks a healing potion in every in-match equipment panel. A bandage channels for 3 s then restores 35 health over 3 s; a potion channels for 0.5 s then restores 50 health. `Archer` plays the merged `Bandage_Wrap`/`Potion_Drink` clips and sockets a procedural roll/bottle; damage, attacks, jumps, rolls, steps, cover changes and gear changes cancel the channel. The host owns the channel and heal on authoritative actors. The delve maps `6`/`7` to the same `"consume"` action the arena uses; the frontier calls `use_consumable` directly. `tools/prepare_consumables.py` merges only the two new clips into the original GLB.
- `1` equips the selected bow; `2` equips the selected sword; `3` equips the single dagger; `4` equips or stows the shield; `5` toggles dual wield. The shield is legal with the dagger or **any one-handed sword** (`sword_index` 0 or 1, including the shortsword); switching to a bow, greatsword, staff or dual wield stows it. Bow and sword sizes are selected independently with mouse buttons, not number-key cycling.

Key **5** selects dagger-left; the paperdoll can select either legal off-hand weapon. LMB uses left-hand `diagonal_left`; RMB uses right-hand `diagonal_right`, never guard. Wheel up/down retain right-hand stab/overhead, and T throws the right sword. `set_sword(2)` leaves dual mode; `set_weapon("dual")` refuses a greatsword. Session weapon keys do not persist the kit.

Reject while airborne, rolling or cooling down; a step cancels draw/melee/throw/guard, exits cover, and ends on floor loss. Step velocity overrides normal acceleration and slide but not roll. `Archer.set_step(progress,direction)` must be fed every tick (-1 when inactive). It latches the root facing (including a 0.20 s exit hold for the decaying step velocity), opens the hips and chest into the travel, counter-turns the head toward the target, and offsets the leading/trailing feet.
- **G interacts** with a keeper, the town stash, the campfire, a waystone, a delve cache, the rope or the open floor. The inn hatch has no prompt; it is entered by falling.
- **I opens the in-world inventory; P opens the equipment paperdoll; TAB swaps the bound hand pair** in the frontier, arena and delve. `Escape` closes the kit first and only then frees the cursor, cancels a held attack or toggles the captured cursor. While the kit is open, the scene ignores weapon keys, TAB, the wheel and mouse attacks, and opening it cancels a held draw/throw/guard/swing/step. Arena and delve clients still route paperdoll and TAB changes through the host's validated `"loadout"` action; the kit never invents damage, charge or seat state.
- **LMB with a nondual sword or dagger is a diagonal cut**: `diagonal_right` starts at the right shoulder, `diagonal_left` at the left. Accepted local/host cuts alternate; X resets the next side to the newly selected camera shoulder. A rejected local/host attack must not consume alternation. Clients alternate dispatched intents without an extra acknowledgement RPC. **Wheel up** is precision `stab` (0.5 s), **wheel down** is authored `overhead` (dagger resolves to its precision stab), and Ctrl+wheel remains camera zoom. Arena/delve accept the validated `melee` action with hand, variant and aim; `draw` is bow-only, with no separate right-attack action or legacy variant aliases.
- **T** is the held throw input for swords and daggers; LMB and the wheel still perform melee. Release throws at most one weapon. It is intentionally separate from the melee input.
- RMB guards with a sword or dagger while grounded and READY, and still requests a cover peek when attached. `Combat.block_time` starts at zero on press; for a sword, a hit at or under `Combat.PARRY_WINDOW` (0.25 s) is a parry, a later hit is a standard block. A dagger never parries: every dagger guard hit is a weak block that halves damage, costs `Combat.DAGGER_BLOCK_STAMINA`, and leaves the attacker's swing running. Guarding pauses stamina recovery, standard sword blocks spend `Combat.BLOCK_STAMINA`, push the defender away and reset the attacker's swing to neutral (no retained recovery to punish), and only front-facing melee is blockable. Releasing RMB, attacking, rolling, jumping, equipment changes, death and movement input loss clear the guard. The defender keeps the guard after a parry and can swing immediately; the parried attacker is locked out for `Combat.PARRY_STAGGER` (0.8 s). With a shield equipped, RMB raises the shield instead: it is a full front block (never a parry), spends `Combat.SHIELD_BLOCK_STAMINA` (18), and covers the chest/head with a moving physical shield body; the dagger weak block is bypassed while the shield is up.

### Quick steps, abilities, hit stagger and multiplayer feel

- `scripts/dodge_step.gd` owns the grounded side step shared by both controllers. Keep the player's 2.95 m / 0.30 s defaults, 7 stamina and 0.55 s cooldown; `velocity()` is normalized so its sampled travel matches the instance's `travel`. `travel`/`duration` are per-instance: the cinder devils configure **1.475 m / 0.22 s** and must not shrink the player's step. Reject airborne/rolling/cooldown starts, and keep step velocity above slide but below roll in the movement override order. `Archer.get_animation_state()` uses presentation phase `STEP` with progress in `time` (no new payload key); replicas set `_step_direction` from the snapshot velocity. The frontier and arena share `playtest/sidestep_lab.tscn` for visual tuning.
- `scripts/damage_numbers.gd` is the shared scrolling `Label3D` presenter. Arena hosts spawn from real damage and clients spawn from the health delta in `apply_snapshot`; frontier enemies and the player use the same presenter. Do not add a damage-number network message.
- Abilities are data, not new `Combat` branches. `AbilityRules` is the only definition table; `granted(rig)` resolves each hand from the held item (main hand follows the visible weapon mode, off hand follows an equipped shield) and an empty main hand keeps the legacy unarmed **Charge**. `AbilityRunner.activate()` rejects an empty grant, airborne, stagger, guard, cover, roll/slide/step, non-READY, cooldown and insufficient-stamina starts, spends the cost once, locks facing/travel and starts the data cue clock; `Archer.begin_ability(definition, direction)` plays the declared clip and carries the lean, spin and bow draw curve. The animation state packs the ability table index and slot in `draw` and the elapsed clock in `time` under phase `ABILITY`; replicas decode the index, so no new snapshot key is needed. `ArenaActor.snapshot()` also carries `stamina`, the active index and per-slot cooldowns. Effect cues fire from the clock on every peer; only the authority applies `Combat.ability_strike`/`ability_blast` damage and authoritative projectiles. Weapon skills currently cost **1 stamina** and swapping the granted weapon clears that slot cooldown for testing. Bow skills solve both arms from `bow_draw`; the greatsword spin turns the model while the ring is applied once. `Combat.ability_strike(radius, arc, damage, stagger, ring, sight)` reuses the melee contact/block/blood path, and `Combat.ability_blast(centre, radius, damage, stagger)` damages bodies inside a spell burst. Do not add a damage branch to the Runner and do not let replicas apply damage.
- `Combat.stagger_from_damage(amount, max_health)` rolls the attack interruption from the hit's share of max health: under **5%** can never interrupt, **50%** or more always does, and the chance ramps linearly between (`Combat.stagger_chance` is the pure query). A landed roll staggers for `0.08 + 1.2 × fraction`, capped at **0.62 s**, cancelling movement intent, guard, draw, throw and swings. The return value is also the rig recoil passed to `Archer.set_hit_react(seconds)`, so a shrugged chip still rocks the pose and cancels a consumable without breaking the swing; the remaining react time rides in the animation snapshot as phase `STAGGER` with `time`, so replicas flinch without a new payload key. A weakly blocked dagger hit still applies half damage but **does not** stagger or drop the guard; the raised dagger absorbs the impact. Parries keep the fixed `PARRY_STAGGER` (0.8 s).
- `ArenaActor` buffers timestamped snapshots and interpolates between them (`interp_delay` 0.12 s remote, 0.05 s local client seat, 0.15 s maximum velocity extrapolation). Do not go back to an exponential `lerp` toward the newest position. Respawns/teleports snap and clear the buffer.
- Fighters use collision layer 4 but **mask only 1** (world). Actor-to-actor body collision is intentionally absent; `_separation_velocity` adds a bounded push only below 0.46 m centre distance so players can measure a stab without being shoved off aim. Blades and projectiles still query layer 4.
- `scripts/net_cache.gd` (autoload `NetCache`) persists the last player name, host address, UDP port and join mode (`arena`/`delve`) in `user://net_cache.json`. The title Join form and the standalone arena lobby read it; successful host/join validation writes it. Keep script-mode tests on `user://net_cache_test.json`.
- `scripts/arena_world.gd` is a **64 × 64 m** field (`LIMIT = 32`) with the original centre trees/stone cover retained plus flank cover. `ArenaActor.bounds` is set from `World.LIMIT-0.3`; do not reintroduce the old ±21.7 clamp.

### Running slides

- C's new crouch intent during an achieved grounded sprint starts `RunningSlide` in both controllers. Require at least 6 m/s actual planar velocity, sprint input/stamina eligibility, and no existing crouch, cover or roll. Stationary Shift+C, walking and repeated true crouch intent must not manufacture or restart momentum.
- `try_start(body,stance,sprinting,rolling)` sets crouch intent; `step(delta,body,stance,direction,rolling)` precedes velocity selection, and `after_move(body,actual_velocity)` sees achieved post-collision movement. Keep `CoverMovement` as the sole capsule/camera stance owner. Slide velocity overrides ordinary acceleration only while active; roll remains the final override.
- The 0.75 s slide decelerates from 10.5 to 2.2 m/s, allows at most 36 degrees steering from entry, and persists without held movement/Shift. Continue normal sprint stamina drain; finish crouched. C cancels, successful jump/roll or cover attachment cancels, and floor loss/blocked forward movement ends it. Blocked headroom must not expand the capsule or cancel a rejected jump. Death/revive/camp and stale arena input clear sliding.
- Grounded combat remains available. `Archer.set_slide(progress,direction)` runs after `set_cover` and before the controller's pose updates; inactive progress is -1. The rig layers a fixed-length, asymmetric planted slide over authored crouch, suppresses stepping, and preserves upper-body weapon actions. Preserve heading through the exit blend rather than resetting it to world-forward.
- Animation snapshot `slide` is a compact `Vector4(progress,direction.x,direction.z,blend_weight)` so individual actor RPCs stay below ENet's MTU, including maximum-length UTF-8 names. Roll facing uses the existing replicated yaw, not a redundant direction field. Replicas apply physical cover before the animation snapshot. Clients still submit boolean crouch intent, never slide speed/position/pose claims.

### Cover and shoulder controls

- F toggles grounded, geometry-derived cover within 1.35 m. Both controllers use `CoverMovement`; WASD projects onto the contact tangent. Supported full-capsule sweeps follow slopes, curved/faceted offsets and contiguous collider seams without shape/RID identity locking. Genuine edges and hard corners still stop movement. Attached movement is 2.2 m/s, or 4.2 m/s with Shift and normal stamina/exhaustion, including crouch.
- RMB holds a manual top/left/right lookout. Side destinations try 0.45/0.55/0.65 m in order, requiring supported ground, a swept clear capsule and a finite-width forward firing corridor. Low-cover classification also checks deeper inward geometry so an inset rock face cannot invent a top peek. Keep one endpoint latched, and normalize signed lean against its selected extent. A blocked opposite-side request may retuck and resume sliding; a stationary blocked same-side request cannot jump to a longer endpoint. Use the same 2 cm protected-return tolerance as arrival, not a submillimetre latch that terrain recovery can keep locked. Bow attacks OR automatic exposure with manual input; melee bypasses this gate by exiting cover.
- A draw begun already exposed by RMB keeps manual ownership: releasing RMB retucks without canceling the held draw, including sliding away from the edge. Releasing that bow while tucked requests exposure again; blocked release cancels safely. A direct tucked bow draw owns exposure through RELEASE, then retucks unless RMB remains held. Stop, equipment changes, jump/roll, death/respawn and lost cover clear pending bow intent.
- X explicitly selects left/right lookout and smoothly swaps the camera, not weapon handedness. Capture horizontal view-right on cover entry, a new READY draw, manual RMB press or X. Preserve it through release/return and free look; do not recapture on mouse-up/Q-up. Both controllers feed `cover.view_right` before eligibility/step. Camera smoothing advances once per render frame; aim queries call `resolve()` without advancing it. Preserve swept-volume obstruction and overlap recovery.
- C toggles manual crouch while grounded and not rolling, with captured-cursor movement guards; achieved sprint-to-crouch starts the running slide described above. Armor remains equipment-button-only. Outside cover, ordinary crouch moves at 2.2 m/s and disables sprint. F exit preserves manual crouch. Standing checks headroom; never expand a capsule into an obstacle.
- Cover owns capsule height and smooth `crouch_amount` (0–1), even outside cover. Run `cover.step(delta,direction,peek,side,fast)` every physics tick; use its returned velocity only if cover was active before the call. World-space `lean` is UP times physical rise for low cover, or the signed tangent times physical lateral exposure at tall edges, including retuck. `set_cover(active,normal,crouch_amount,peeking,lean)` runs before locomotion/roll pose updates in both modes and replicas. Keep cover data in the single physical cover snapshot, not duplicated in `get_animation_state()`; apply it before `apply_animation_state()`. Camera height follows crouch outside cover too.
- The rig layers authored `Cover_Lean_Top/Left/Right` pelvis/spine/head deltas in the cover frame so aiming cannot reverse a lean. Facing blends from the protected outward stance toward the aim point with exposure, including idle peeks and retuck. Apply the layer before foot and weapon corrections; preserve sword grips and actual blade sweeps. Retuck must keep its protected anchor until the capsule returns, even with movement held.
- Authored `Crouch_Idle_Loop` / `Crouch_Fwd_Loop` replace the crouched stance/steps, using the JSON stride estimate and actual speed for cadence. Layer only the lower body during bow/sword actions and two-handed carry; preserve overall 0.58 m pelvis lowering and fixed-length planted legs. Side peeks stay crouched; blocked top peeks cannot expand the collider or invent exposure.
- Space caches grounded state before `prepare_jump()`; blocked standing headroom prevents takeoff. Otherwise it exits cover, clears manual crouch and peek latches, restores the standing collider and performs the existing jump/roll. Apply queued jump velocity even if stance preparation changed the floor cache. Death, respawn and camp return use `cover.reset()` and clear held intent.
- Arena validates boolean crouch intent and lookout context (`pressed`, horizontal unit `right`, ±1 `side`). The host derives all geometry, anchors, exposure and collider height. Reliable peek-context messages precede draw/release without fabricating RMB presses. Aim-bearing movement/action RPCs include the observed own-actor snapshot tick, validated against snapshots actually sent. Keep accepted aim and tick atomic: stale samples cannot overwrite newer aim, but valid stale reliable release intent is not dropped.
- Remote `Combat.cover_aim_ready` requires an aim acknowledging the current physical exposure epoch. Reset that epoch on retuck, side transition, exit and lifecycle reset. Keep charge frozen until fresh exposed-camera aim arrives, then run the normal shaft check. Host/local/bots and noncover release are unchanged. Existing input_age >0.65 handling cancels automatic/frozen cover intent; do not add retry timers or allow a delayed shot after input resumes.

### Bow charge and recovery

- `Archer.BOW_DATA.draw_seconds` is the complete time to full charge: small/medium/large currently take 1/2/3 seconds. Raising is included, not an extra delay before charge begins. Base launch speeds are **66/84/102 m/s** for the shortbow/recurve/longbow; partial charge scales speed from 45% to 100% alongside damage.
- `draw_amount` drives the bar, string tension, and damage fraction. Half the draw duration means half damage; for the longbow, 1.5 seconds gives 50% of its base damage.
- Preserve the action sequence: `READY` → `DRAWING` → `HOLDING` if fully charged → `RELEASE` → `RECOVER` → `READY`. Release is also valid during `DRAWING`; holding at full charge never auto-fires.
- In cover, an early bow release sets replicated `rig.charge_frozen`: charge stops at input release while the raise clock continues. `Combat` fires once only after physical exposure and the 0.30-second raise; waiting never increases damage. Non-cover release timing remains immediate.
- There is no separate bow cooldown or movement recovery penalty. Readiness follows the actual release/re-nock animation through `get_bow_recovery_progress()`. The current follow-through is 0.28 seconds and arrow retrieval/re-nocking is 0.95 seconds.
- Every shot, including zero/partial charge, spends the nocked arrow and completes recovery before another draw. Equipment swaps, cancellation, or rolling cannot skip/restart that recovery. Canceling an unreleased draw does not spend its arrow.
- Carry leftover frame time from release into recovery. Do not add a frame-dependent extra delay at phase boundaries.
- Aim remains a world-space point from the camera ray, not target tracking or gravity compensation. Start the query at the projected actor position plus `cover.camera_height()` and exclude the shooter and the attached cover body through `CoverMovement.attached_surface()` (host-cached, replica-derived from `normal`) so top peeks can fire over the wall you are posted against. Never choose the query start from the animated muzzle: it feeds bow facing/raise back into targeting, skips close crosshair targets and makes shoulder convergence unstable. Aim the bow from its cheek anchor. Before a cover release, sweep the actual nock-to-tip shaft with finite radius and an initial-overlap check. A fresh exposure gets `Combat.SHAFT_SETTLE_GRACE` (0.15 s) for its lean/bow pose to settle before a blocked shaft is treated as permanent; a settled obstruction still cancels pending release/frozen charge.
- A released arrow travels on the center crosshair ray, not a converging line from the bow tip. `Combat.set_camera_ray` validates a muzzle point on that ray (preferring the point nearest the rendered tip) with a spawn-overlap check, a clear path to the aim point, and a clear link back to the rendered tip; if any check fails, it clears the override and the arrow uses the rendered tip. The arena sends the client camera-ray origin with aim actions and movement, validates it within 12 m of the actor, and replicates the captured visual start in the shot event. `Arrow` blends its rendered shaft from that visual start to the authoritative path over `VISUAL_BLEND_SECONDS` (0.12 s) and snaps it to the impact point. Ordinary projectile collision alone applies damage. Never remove the fallback: a camera-ray spawn buried in posted cover must not shoot through it.

### Damage zones

- `scripts/hitbox.gd` owns the **2x head multiplier** and the zone profiles for humanoids, the wolf, the sentinel and the cinder devil. Head zones are logical damage volumes against the single physical body capsule; do not add extra collision shapes, layers, areas or RIDs. That keeps arrows, blades, movement and cover on the existing authoritative collision path.
- Zones are upright cylinders around animated joints: arena actors read the rig's `Head` bone, the wolf reads its imported `head` bone, the sentinel uses its stone head and the devil reads its animated procedural head. Crouch, cover lean, rolls and the wolf's bite move the zone with the skeleton.
- Diagonal cleaves always use base body damage, never incidental headshots. Arrows classify their actual ray point with `Hitbox.is_headshot`; precision stabs/overheads use `Hitbox.blade_headshot` with swept blade segments and radius, never a shape query's arbitrary rest point. Thrown weapons retain their projectile head-zone path. Apply the 2x multiplier before armor only for these precision/projectile contacts.
- Receivers take a `headshot` boolean: `ArenaActor.take_damage` / `receive_melee` and `enemy.gd.take_damage`. Apply the multiplier before armor and before the frontier damage label. Arena damage stays host-authoritative; do not add a headshot field to snapshots or trust client classification.
- `melee_roll_regression` intentionally expects the greatsword's vertical cut to deal 2x and the one-handed cuts to deal base damage. Do not flatten those expectations to a single value.

### Blood and wounds

- Blood is **presentation only** and must never gate damage, hits, blocks, stamina or network authority. Spawn it only where damage was actually applied: unmitigated melee contact, a projectile that damaged a body, a real `take_damage`, and a replicated health/weapon-blood delta. Parry, standard block and shield block spawn no spray; a weak dagger block keeps only the half-damage wound.
- `BloodFx` is the static entry point (`impact`, `wound`, `stain_weapon`, `stain_weapon_node`, `stain_projectile`). `field_for` lazily creates one `BloodField` under `get_tree().current_scene` (tree root in script-mode tests). Do not add a global autoload or persist the field across scenes.
- **60 seconds** is the contract: `BloodFx.LIFETIME = 60.0`, fading over the final `FADE_SECONDS = 3.0` and then freeing. Surface patches fade through `GeometryInstance3D.transparency`; rig/weapon coatings shrink. Budgets are `BloodField.max_surface_stains = 160` world patches, 10 wounds per rig and 8 coatings per weapon; recycle oldest-first. Do not remove the budgets without measuring a crowd fight.
- The renderer is **GL Compatibility**, which has no `Decal` support. Keep ground blood as physics-conformed `ArrayMesh` patches and body/weapon blood as bone- or weapon-parented meshes. Never replace this with `Decal` or a `next_pass` stain shader.
- Body blood attaches to the nearest `Skeleton3D` bone through a reused, per-bone `BoneAttachment3D` (`BloodBone_<index>`), which `BloodField` frees once its last stain expires; never leave empty attachments behind. Weapon blood attaches to the drawn weapon node so it follows swings, sockets and equipment swaps. Player weapon anchors come from `Archer.blood_weapon_anchor(hand)`; enemies expose `blood_rig()`, `blood_scale()` and `blood_weapon_anchor(hand)`, and `devil_visual.gd` provides `blood_anchor()`/`weapon_anchor()`.
- Body stains must lie **on the garment**. `BloodSurface.body_for(rig)` measures the visible skinned cloth once per rig (bone radial profile over 24 x 12 cells, plus a thinned whole-garment sample) and caches it per `body_for` signature; swap-invalidating is the visible **skinned mesh name set**, so armour changes remeasure while a raised bow, a dropped weapon or a death pose do not. `prepare_pose` skins the garment sample into the carrier's current pose and `add_patch` lifts each splash onto the **outermost** layer under it — without that step a belt or a sleeve weighted to a neighbouring bone swallows the stain. Primitive rigs (cinder devil, ruin sentinel) are measured as their own triangle soup and parent stains to the limb `MeshInstance3D`. Never go back to free-floating flattened spheres: they read as blobs beside the body.
- Splash size is clamped by `BloodSurface.patch_extent` to the measured strip; a patch bigger than its strip collapses into a flat sheet. `cluster` places the splashes on the strip (around the blow for primitive rigs) so one hit is readable from every side of the fight.
- Projectiles are special-cased: `BloodField.stain_projectile` builds a short curved smear on the shaft behind the head (plus two specks), sized from the shaft, not the blade path. Arrows must never receive a blade-sized coating — that is the "goo" look.
- The first blood event on a rig costs a one-off measurement (~30 ms on the ranger; cached afterwards) and each later wound is ~1-2 ms. Keep it there: remeasuring per wound or per frame is a stutter.
- Each wound and each weapon coating is merged through `SurfaceTool` into **one** `MeshInstance3D`; do not add a separate node per droplet. Ground splats stay one mesh per stain. This keeps a bloody crowd inside the draw budget.
- Networked clients derive wounds from snapshot health deltas and weapon coatings from the snapshot `weapon_blood` tally (`ArenaActor.note_weapon_blood`, inherited by `DelveActor`). Do not add a dedicated blood RPC or trust client damage claims for blood.

### Thrown weapons

- Hold **T** with a sword or dagger to charge; release to throw one copy. Melee stays on LMB, wheel up (stab) and wheel down (overhead). `Archer.begin_throw()` uses dedicated phases `T_DRAW` → `T_HOLD` → `T_RELEASE` → `T_RECOVER` so the charge never collides with bow phases or melee and the snapshot phase stays short. Keep the phase names in `Combat.advance`, `get_attack_interval`, `update_aim`, both HUDs, and the animation-state replica path.
- Charge time is the equipped weapon's `seconds` (1/2/3 s swords, 0.5 s dagger). Damage is `base damage × clamp(charge,0,1)` via `Combat.throw_damage`; the projectile uses `ThrownWeapon`, the arrow's gravity (-4), swept ray collision, head-zone multiplier, and stops on the first contact. It is not `receive_melee`, so guards never parry a throw.
- Spent throw timing is `Archer.RELEASE_SECONDS` + `Archer.RECOVER_SECONDS` (0.28 + 0.95). `Archer.get_recovery_progress()` covers both bow and throw phases. Throwing gates on `Combat.melee_progress >= 1`, like melee, because it uses the same weapon.
- Endless supply is deliberate: throwing never consumes a paperdoll or backpack item, and the equipped weapon never disappears permanently. `_sync_weapon_visibility()` hides it only during `T_RELEASE` and restores it in recovery. Do not decrement the backpack or mutate `sword_index`/dagger availability.
- Throw pose samples the existing authored melee clip (`_throw_clip_time`): the chamber through charge, the authored strike on release, and the follow-through as recovery. Do not invent a procedural throw or reuse bow arm IK. The greatsword carry/guard overlay is disabled during throw phases.
- Cover behavior mirrors the bow: `Combat.begin_throw`/`release_throw` use the shared exposure, frozen-charge, and `cover_aim_ready` gates. `_cover_throw_clear` sweeps the exposed hand down the aim line for 1.2 m; obstruction cancels instead of throwing through cover.
- Arena: clients send `"throw"` / `"throw_release"` (aim + observed snapshot tick) and the host validates them like draw/release. `ArenaActor.thrown_weapon` feeds `Arena._on_thrown_weapon`, which spawns the authoritative projectile and broadcasts `_throw_event` reliably. Replicas spawn visual-only projectiles with `authoritative_damage = false`.

### Swords, daggers and state isolation

- Standard diagonal attacks sweep a frontal sector chronologically through the active stroke, not a thin blade-only contact and not an instantaneous whole-arc hit. Per-hand rig APIs are `melee_variant(hand)`, `is_diagonal_swing(hand)`, `melee_cut_progress(hand)` (0..1 through the clip), `melee_cut_curve(hand)` (release curve), `melee_half_angle(hand)` (radians), and `melee_reach(hand)`. Dagger: 0.42 s, 1.2 m, 75-degree half-angle. Shortsword/arming/greatsword: 0.60/0.78/1.02 s, 1.8/2.1/2.5 m, 80/85/90-degree half-angles. Staffs: 1.6/1.5 m middle-grip reach, same greatsword damage/timing and 90-degree half-angle. Bigger weapons visibly cock the hands up and behind the striking shoulder, pitch the blade up outside the active sector, hold the loaded pose for a beat, then cut down across the torso and follow through low, with larger arcs and the greatsword support hand staying on the hilt.
- Diagonals run one shared clock: load to 30%, release 30-45%, follow-through 45-65%, cushion to 75%, recovery to 100%. `SWING_LOAD_END`/`SWING_FOLLOW_END`/`SWING_SETTLE_END` and `_swing_drive()` define that clock; `melee_cut_curve()` is the same curve the visible arm uses, so never give `Combat._sweep_cleave` a different angular curve. The kinetic chain is explicit in `SWING_CHAIN_PELVIS`/`CHEST`/`CLAVICLE`/`BLADE`: each joint runs the same curve on its own offset, so the pelvis turns first, the chest follows, the clavicle drags the shoulder and the hand and blade tip arrive last. `DIAGONAL_BLADE` owns the hilt path (`yaw_load`/`yaw_cross`/`rad_load`/`rad_cross`/`fwd_load`/`fwd_cross`/`up_load`/`up_cross`), the blade aim (`blade_load`/`blade_cross`/`tip_load`/`tip_down`) and the body shares (`pelvis_*`, `chest_*`, `lean_*`, `clavicle`). `yaw_cross`/`blade_cross`/`tip_cross` are magnitudes mirrored by the variant side; the hand yaw must actually sign-flip through the drive, so the hilt crosses the centre line while the tip passes the sector edge. A free off hand reaches forward as a counterbalance; a shield or focus keeps its guard.
- Diagonal body motion samples the existing `Sword_Overhead` for the plant, hip drop and knee drive, but the torso belongs to the swing: `_apply_melee_swing_path` rebuilds `spine_01`/`spine_02`/`spine_03` as absolute rest-frame yaw and pitch shares (0.34/0.68/1.0 of the chest value) instead of stacking deltas on the authored chop, so the chest extends over the trailing hip on the load and crunches through the strike instead of inheriting the overhead's forward hunch. The head gives back most of that yaw and pitch (`head_yaw`/`head_pitch`) so the gaze stays on the target. Mirror the leg pairs for `diagonal_left`. Include primary hand and variant in pose-transition identity so overlapping cuts blend instead of popping.

A shared two-handed hilt also keeps 0.30 m of clearance ahead of the shoulder line so pulling it back cannot bury the hands in the chest. - Entry is by **falling through the `SunkenDelveHatch` inside the Wayfarer Inn** in Hearthstead. `range_world.gd` omits the terrain cell under the hatch and `main.gd._physics_process` detects `world.is_over_delve_hatch(player.global_position)` below `y < 2.25`; there is no G prompt. `main.gd._enter_delve` arms `Session` with `delve-solo` (normal) or `delve-host` (when `Host Tailscale.cmd` supplied `--delve-host`/`--delve-port`/`--delve-name`) and loads `delve.tscn`. A solo entry is still a real ENet host; clients join through `Session.arm_delve("delve-join",...)`.
- `Host Tailscale.cmd` launches `main.tscn` with `--delve-host --delve-port 7777 --delve-name "%USERNAME%"`. `main.gd._read_arguments` stores that intent; `_enter_delve` uses it. Normal `Play.cmd` opens the title screen.
- The run is host-authoritative: `delve.gd` owns player movement snapshots, devil AI/snapshots, depth/phase, room kind/cycle, the pentagram ritual, seals, cache, rope, hole, rewards and the party-wipe check. Clients send movement/aim/action intents and receive `_receive_snapshot`, `_devil_snapshots` and reliable `_run_state` (depth, phase, room, cycle, ritual, pentagram, wave_total, wave_number, remaining, timer, seals, chest, rope, hole, party). A client calls `world.apply_room` only when the replicated room/cycle changes, then restores sealed/rope/hole/pentagram/beacons. Never let a client claim run state.
- The scene starts by dropping every active player from `world.drop_center` (y=8) into the room. Phase contract: `ALTAR` (sanctuary only; party lands, walk to `world.altar_position` and press **G**) → `RITUAL` (3.2 s; pentagram appears and the ritual plays) → `WAVE` (room sealed, late-weighted random spawns) → `CLEARED` (barriers down, 2.2 s cache delay, chest spawns, rope lowers, floor hole opens) → rope (`ascend_to_surface` → `main.tscn`), hole (`descend_next_depth` → `depth += 1`, room swapped, drop again) or `GAME_OVER`. Odd depths are the sanctuary, even depths the Ossuary Pit; the pit enters `DROP` first and starts the wave only after every alive human lands (below y=1.5, 0.3 s grace). There is no `ASSEMBLY`, `COMPLETE`, fixed wave count or resume checkpoint. Beacons are refreshed per phase: altar only in `ALTAR`, rope/hole only once lowered/open.
- Wave plan: the **base** is 26 in both rooms at cycle one — sixteen imps and ten devils — over 30 s in the sanctuary and 40 s in the ossuary, and `26 + 2*(cycle-1)` / `26 + 3*(cycle-1)` after that. Every wave, **cycle one included**, adds the five starting-court species (`hell_goat`, `succubus`, `spawn`, `beast`, `gargoyle`) and `min(1 + cycle, 4)` **ranger clones** on top of that base, interleaved by `_interleave` so they arrive through the schedule instead of as a late clump. `wave_total` is `roles.size()`: cycle one is 33, the cycle-two sanctuary 36. Spawn times are `at_i = duration * pow(i/(total-1), 0.6)` (late-weighted). Positions come from `world.spawn_points` with a deterministic RNG (`run_seed`, `depth`, index), rejecting under 3 m from a standing ranger and under 1.6 m from an already-picked spawn. `--delve-rush` scales only the spawn clock (8x) for tests; `wave_plan()`, `wave_total` and `wave_number` expose the plan. `Devil.configure(id, weapon, depth, role)` applies the role profile (`imp` 0.62 scale / 12 hp / 5 dmg / 4.3 m/s, `devil` 1.0 / 24 / 8 / 3.4, `bonefiend` 1.15 / 42 / 13 / 3.5, `brute` 1.38 / 78 / 20 / 2.9) before depth scaling (`health 1+0.28*step`, `damage 1+0.15*step`, speed capped at 1.35x). The five species read `DevilMob.PROFILES` (one profile table), keep their imported GLB, proportions, claw cadence and authored head/strike anchors, fight bare-handed, and are scaled by `COURT_HEALTH_SCALE 0.45` / `COURT_DAMAGE_SCALE 0.65` before the same depth curve so a depth-one wave is not multiplied by four. `spawn_at` places the body and plays the emerge sigil; the snapshot carries `role`, and replicas rebuild the matching rig family (`DevilVisual` for depth roles, `DevilMobVisual` for species). `ROLE_RANGER` entries branch to `ranger_clone.gd` and go through `_clone_snapshots` instead of the devil stream.
- Cache rewards: opening the chest once pays `40 + 30*depth` gold and, on `LootRules.drops()` (10%), one deterministic item from `LOOT_TIERS` selected by depth and `run_seed + depth*7`. The host grants locally and broadcasts `_reward_event(depth,gold,item_id)`; every client grants to its own `PlayerState`. Do not double-grant on the host.
- Weapon drops: when an authoritative delve devil dies, `_on_devil_died` calls `_drop_devil_weapon`, which rolls `LootRules.drops()` (10%) before spawning a `LootPickup` at the floor under its corpse and broadcasting `_weapon_drop_event(item_id,at)`; every client spawns its own local pickup from `held_weapon_id()` (dagger→iron dagger, sword→shortsword). Pickups are armed immediately because they land away from the killer, and `_collect_loot` still banks them through each peer's `PlayerState`. Replicas drop no duplicate on `_die(false)`; only the host announces the reliable event.
- World contract: `DelveWorld.LIMIT=17.0`, `ROOM_SANCTUARY`/`ROOM_OSSUARY`, `apply_room(kind, cycle)` (idempotent rebuild), `room_title()`, `has_altar()` (sanctuary only), `palette()`, `spawn_points`, `altar_position=(0,0.05,-4.0)`, `chest_position=(0,0.06,0.0)`, `rope_position=(5.2,0.05,3.0)`, `hole_position=(-5.2,0.05,3.0)`, `hole_radius=1.05`, `drop_center=(0,8,0)`. There are **no gates**: `set_sealed` toggles additive emissive archway barriers with no colliders. `set_rope_lowered`/`set_hole_open` own rope/hatch presentation and `is_in_hole(point)` is the descent trigger. Tests address the `Rope`, `FloorHole`, `Altar` (sanctuary only), `Pentagram`, `BeaconAltar`, `BeaconRope` and `BeaconHole` nodes.
- Decision beacons (`scripts/delve_beacon.gd` + `delve_beacon.gdshader`) are additive TIME-shimmer light columns with a ground pool, a restrained OmniLight and a billboard title (`ALTAR`, `ROPE OUT`, `DESCEND`). The pentagram (`scripts/delve_pentagram.gd` + `delve_pentagram.gdshader`) is a five-point star plus rings with a shader TIME pulse, ritual embers, five point-orbs, a spinning outer ring and a central column. Motion lives in shaders/tweens/particles — never per-frame GDScript — and none of it gates gameplay.
- `delve_regression` covers the sanctuary fall-in, the pentagram ritual, the 10-enemy late-weighted random wave, clear/cache/exit beacons, the ossuary descent (`DROP` → ritual → 20 elites from the role profiles), depth-three sanctuary recycling with a changed palette and the rope return; `delve_entry_regression` drives the town gate, the physical hatch fall, the arena portal and the rope return; `delve_network_regression` joins a second real ENet process and verifies room/ritual/phase/wave/cache/rope/hole replication through the ossuary.

### World art and scenery (frontier and arena)

- Scenery is presentation only. `range_world.gd` terrain heights/routes/clearings, player and enemy spawns, interactables, waystones, `_reserved` gameplay clearings and village/fort collision remain authoritative. `arena_world.gd` keeps `LIMIT = 32`, the four spawn points, the 14 real cover-tree positions and their **0.55 m radius / 5.5 m height** cylinder colliders; cover and network regressions attach to those exact bodies. Art changes may replace meshes and materials, never that geometry.
- Both scenes build from `WorldStyle.frontier()` / `WorldStyle.arena()`. `TreeKit.build_variants(species, seed)` generates deterministic tapered trunks, real branches and alpha-scissored leaf/needle cards (UV2 wind weights, crown-interior vertex shading). `WorldScatter.batch` packs instances into per-chunk `MultiMesh`es with instance tints, explicit AABBs, visibility ranges and a shadow choice. `GrassField.build` places grass/flower/fern clumps with reserved/slope rejection and chunk distance culling. `WorldEnvironmentKit.build` owns the 4096 × 2048 photoreal panorama (linear-light Rayleigh gradient, sun disc authored at the key light's YXZ direction, perspective cumulus deck, cirrus and aerial haze), sky ambient, haze-matched fog, filmic grade and the shadowed sun.
- Terrain vertex colour is a value/hue multiplier; **vertex alpha is the dirt weight** consumed by `scripts/world/shaders/terrain.gdshader`, and world-normal slope selects the rock texture. Do not bake lit colour into the heightfield or bypass the splat shader for the main terrain.
- World textures are authored PNGs under `assets/world/textures/` generated by `tools/world_textures.py` (deterministic; manifest `assets/world/world_textures.json`). Keep them lossless with mipmaps and `detect_3d/compress_to=0`; alpha atlases use an 8 px inset per side. New texture ids go into `TextureLibrary` caches and, for atlases/buildings, `ATLAS_LAYOUTS`/`BUILDING_KINDS`.
- Grass and foliage use alpha scissor, not sorted transparency. Grass casts no shadows and its shader `fade_end` must equal the chunk's `visibility_range_end`; trees are chunked with shadow casting. There is no per-frame GDScript for scenery.
- Frontier tree collision follows the authored trunk (trunk height and radius), never the canopy; boulders use simple sphere colliders. Do not reintroduce the old single-cylinder/cones/spheres tree primitives or a flat-colour terrain fallback for the shipping scene.
- `tests/world_art_regression.gd` is the relevant determinism/import/budget check. It does not replace rendered inspection: launch the frontier and arena, confirm the changed sky/terrain/tree/grass surfaces in the actual camera, and report draw calls/primitives. Isolated shader-compile stalls after a teleport are not steady-state performance; sample after the scene settles.

## Cross-mode change checklist

1. Change the shared rig/combat/roll behavior first, then migrate both controllers and their callsites.
2. For new animation state, update both rig serialization methods and review actor snapshots/replica application. The host owns combat and damage; clients submit input/aim, not charge or damage claims.
3. Update the in-world kit (`world_ui.gd`), both match HUDs, the town/frontier HUD, equipment hints, and the README when controls or timing change. Never leave labels describing a removed cooldown, gesture, or launch path.
4. When gear, capacities, prices or equipped-kit behavior changes, update `PlayerState`, `EquipmentRules`, `ArmorData`, `world_ui.gd`, the town keepers/stash and both mode-start loadout paths, the network packed state, `paperdoll_regression`, `town_services_regression` and `world_ui_regression` together. Equipment is ten slots separate from the backpack; do not collapse armor to one set index or put equipped gear back in the backpack.
5. Check weapon swaps, cancellation, airborne restrictions, respawn, and host/client behavior at the affected state boundaries.
6. For world-art changes, update `WorldStyle`/`TextureLibrary`/shaders, run `world_art_regression`, and inspect rendered frontier and arena captures. Keep terrain, route, spawn, waystone and arena cover geometry unchanged unless gameplay behavior is intentionally changing.

## Restart and delivery

Godot keeps loaded scripts in memory. When asked to restart, identify processes by executable path and project arguments, preserve their scene/network arguments, close only this repo's game instances gracefully, and relaunch them. Do not kill unrelated Godot editors/games or silently force-kill a nonresponsive process. Restarting clears session-only frontier progress and disconnects a running match; reconnect clients to a restarted host.
