# Ironwood Archer

Work from the repository root containing `project.godot`. Paths below are repository-relative, not relative to this skill directory. Treat the current code and the user's requested behavior as authoritative; this skill records the existing contracts, not a prohibition on intentional changes.

## Orient before editing

1. Read the relevant portions of `README.md` and locate the affected symbols and callers. Preserve existing GDScript, signal, and scene conventions.
2. Separate shared gameplay from controller-specific input. A frontier-only fix is incomplete when the same feature is available in the arena.
3. Inspect the current launcher and setup files before changing the engine version or executable paths. Use the managed engine or the user's `GODOT_PATH`; do not introduce a new toolchain.
4. Check whether a GDScript language server is available before symbol navigation/refactors. If unavailable, use scoped symbol searches and Godot's parser/runtime; do not claim LSP verification.

## Gameplay contracts to preserve

### The Hollow and out-of-raid state

- `project.godot` sets `run/main_scene="res://menu.tscn"`; every normal launch starts in the Hollow. `Play.cmd` therefore opens the hub. `Arena.cmd` still opens `arena.tscn` directly for the standalone lobby and scripted hosts/joins.
- `PlayerState` is the only authority for out-of-raid gear. `INVENTORY_CAPACITY` is **10** and `STASH_CAPACITY` is **20**; both are hard limits enforced by `buy`, `move_to_stash` and `move_to_inventory`. Do not add overflow slots or silently drop rejected items.
- The starting state is the shortbow, shortsword, the five Ranger leather pieces (equipped, seven inventory slots total), an empty stash and 200 credits. Equipped gear stays in the inventory and is marked with `*`; the last copy of an equipped piece cannot be sold or stashed. A duplicate copy may be sold while that slot remains equipped.
- `scripts/menu_hud.gd` is read-only over state: selection lives in the HUD, every mutation is a signal handled by `menu.gd` (`buy_requested`, `equip_requested`, `stash_requested`, `unstash_requested`, `sell_requested`). Keep capacity/affordability checks in `PlayerState`, not only in button enablement.
- `scripts/menu.gd` applies the equipped bow/sword and the five `PlayerState.equipped_pieces()` indexes to its `Archer` preview after each change. Keep the camera framing the ranger between the inventory (left) and vendor (right) panels, the stash panel above the bottom edge, and the modal form inside the viewport. `hub_regression` asserts panel containment, pairwise non-overlap, label clipping, and modal field containment; update it with layout changes.
- Vendors, prices and item stats live in `PlayerState.ITEMS` / `VENDORS`. Selling pays `floor(price * 0.6)`. Bought gear does not auto-equip.
- Persistence writes `user://player_state.json` on every mutation and loads on autoload ready. Unknown item ids and excess entries are dropped on load. Deleting the file restores the starting kit. Never break the format silently; `hub_regression` round-trips it.
- Frontier and arena start from `PlayerState.equipped_index(kind)` for the bow/sword and `PlayerState.equipped_pieces()` for head/chest/hands/legs/feet. In-match slot buttons still change that session's loadout, but those session changes are not written back; only the Hollow's equipped kit persists.
- Frontier rewards use `_award_gold`, which updates the visible session gold and calls `PlayerState.add_credits`. Do not add a second wallet path.
- The arena consumes `Session.take()` once in `_read_arguments`; `--arena-host` / `--arena-join` remain authoritative. Hub practice uses `mode="skirmish"`, which calls `host_game(..., find_open_port=true)` and tries 7777 through 7792 so an existing host never blocks a local practice match; explicit hosting still reports the requested port conflict. A hub host applies its own kit in `host_game`; a joining client sends `{bow,sword,armor}` with `_register`, where `armor` is the 10-bit packed slot state from `ArmorData.pack`, the host applies it to that seat, and the normal snapshots drive the client's presentation. Validate every value in `_apply_loadout` (bow/sword 0..2, packed armor 0..1023); never trust a client's claimed indexes beyond that.
- Hub return paths: the frontier HUD button emits `hub_requested` and loads `menu.tscn`; the arena lobby's **Return to the Hollow** does the same after `leave_game()`. Do not recreate the old frontier/arena shortcut loop.

### Armor slots

- Armor is five independently equipped slots: **head, chest, hands, legs, feet**. `ArmorData.SLOTS` owns the order, `SET_IDS` is `leather/mail/plate/cloth`, and the item ids are `armor_<set>_<slot>`. Each item's `kind` is its slot; `PlayerState.equip` therefore replaces exactly one slot. A legacy whole-set id (`armor_leather`, `armor_mail`, `armor_plate`) remains valid for v1 saves and for tests: equipping it assigns the bundle to every slot, and `is_equipped` treats it as satisfying any slot.
- Guard is additive per piece: mail 3/5/2/3/2% and plate 7/9/4/6/4% for head/chest/hands/legs/feet; leather and cloth contribute zero. `ArmorData.reduction` clamps at 45%. `Archer.armor_reduction()` and both controllers must use it; do not restore a single set-index reduction table.
- The rig's `_build_armor_meshes()` groups the imported leather meshes (`Male_Ranger_Head_Hood`, Body/Belts/Pauldron/Arms, Bracer, Legs, Boots) into slot 0 and the generated `Armor_<Set>_<Slot>` nodes into slots 1..3. `Male_Ranger_Arms` belongs to the leather chest so another chest's sleeves replace the skin arms; every non-leather chest must fully cover the arms. Keep head/eyes/brows outside every group.
- `set_armor_piece(slot,set)` preserves the other four slots; `set_armor_pieces(dict)` and `set_armor(set)` are whole-kit helpers. `armor_bits()`/`set_armor_bits()` use two bits per slot in `ArmorData.SLOTS` order. The network snapshot stores the packed 10-bit value in `armor`; the shield bit is `ArmorData.SHIELD_BIT` (bit 10), never the old bit 2.
- The frontier and arena equipment panels expose five slot buttons that cycle sets for that session and emit `armor_selected(slot,set)`. The hub equips individual items from the inventory; its Quartermaster stock is a scrollable 20-piece list. Do not reintroduce three whole-set buttons.
- The ranger GLB is authored with the armor: `tools/character_armor.py` builds mail/plate/cloth and leather gloves in the rest skeleton with explicit weights, explicit UVs and embedded 512px base-color/normal textures. `Ranger_Base_Calf` is an always-visible dark hose underlayer so short sabatons never expose an empty shin when mixed with the short leather trousers; it is deliberately outside every slot group. The builder is called from `tools/prepare_character.py` after the animations are baked and before cleanup. Keep `Armor_<Set>_<Slot>` names and the `armor.generated` metadata in `ironwood_ranger.json`; the rig reads that metadata to group meshes.


### Input and rolls

- Space jumps; **Shift + Space rolls immediately** from the ground or during a jump. Repeated unmodified Space presses never roll. There is no double-tap window.
- Movement determines roll direction, then facing is the fallback. Keep the single-roll-per-airborne-cycle restriction, normal world collisions, and attack cancellation; a roll is not invulnerability.
- Both controllers pass `event.shift_pressed`. The arena's `jump` action carries an explicitly validated boolean, not a trusted client animation state.
- `1` equips the selected bow; `2` equips the selected sword; `3` equips the single dagger; `4` equips or stows the shield; `5` toggles dual wield. The shield is only legal with the dagger or the medium arming sword (`sword_index == 1`); switching to a bow, shortsword or greatsword stows it. Bow and sword sizes are selected independently with mouse buttons, not number-key cycling.
- Dual wield requires the shortsword or arming sword (`sword_index` 0/1) and holds the dagger in the left hand. LMB performs the left dagger stab; RMB performs the right sword overhead instead of guarding. T still throws the right-hand sword. `set_sword(2)` leaves dual mode; `set_weapon("dual")` refuses a greatsword. The mode is session-only like `1`/`2`/`3`, not persisted in `PlayerState`.
- **LMB is the only held attack input for bows.** Release launches at most one arrow. Escape/equipment cancellation must not fire an arrow or leave a held-input latch active. Q no longer draws; E no longer interacts.
- **Q / E are grounded side steps left / right** relative to the camera (`DodgeStep`: 2.95 m travel, 0.30 s, 7 stamina, 0.55 s cooldown). Reject while airborne, rolling or cooling down; a step cancels draw/melee/throw/guard, exits cover, and ends on floor loss. Step velocity overrides normal acceleration and slide but not roll. `Archer.set_step(progress,direction)` must be fed every tick (-1 when inactive). It latches the root facing (including a 0.20 s exit hold for the decaying step velocity), opens the hips and chest into the travel, counter-turns the head toward the target, and offsets the leading/trailing feet.
- **G interacts** with the campfire and waystones. Keep the HUD prompts on G.
- **LMB with a sword is a horizontal swing** whose start side follows the shoulder camera (`horizontal_right` for the right shoulder, `horizontal_left` for the left); consecutive LMB swings rebound to the opposite side, and X resets the next side to the newly selected shoulder. **Wheel up is a forward stab** (`stab`, 0.5 s, aim-directed sword thrust). **Wheel down is the authored overhead** (`overhead`). Ctrl+wheel keeps camera zoom; plain wheel selects the melee variant.
- **T** is the held throw input for swords and daggers; LMB and the wheel still perform melee. Release throws at most one weapon. It is intentionally separate from the melee input.
- RMB guards with a sword or dagger while grounded and READY, and still requests a cover peek when attached. `Combat.block_time` starts at zero on press; for a sword, a hit at or under `Combat.PARRY_WINDOW` (0.25 s) is a parry, a later hit is a standard block. A dagger never parries: every dagger guard hit is a weak block that halves damage, costs `Combat.DAGGER_BLOCK_STAMINA`, and leaves the attacker's swing running. Guarding pauses stamina recovery, standard sword blocks spend `Combat.BLOCK_STAMINA`, push the defender away and reset the attacker's swing to neutral (no retained recovery to punish), and only front-facing melee is blockable. Releasing RMB, attacking, rolling, jumping, equipment changes, death and movement input loss clear the guard. The defender keeps the guard after a parry and can swing immediately; the parried attacker is locked out for `Combat.PARRY_STAGGER` (0.8 s). With a shield equipped, RMB raises the shield instead: it is a full front block (never a parry), spends `Combat.SHIELD_BLOCK_STAMINA` (18), and covers the chest/head with a moving physical shield body; the dagger weak block is bypassed while the shield is up.

### Quick steps, hit stagger and multiplayer feel

- `scripts/dodge_step.gd` owns the grounded side step shared by both controllers. Keep the player's 2.95 m / 0.30 s defaults, 7 stamina and 0.55 s cooldown; `velocity()` is normalized so its sampled travel matches the instance's `travel`. `travel`/`duration` are per-instance: the cinder devils configure **1.475 m / 0.22 s** and must not shrink the player's step. Reject airborne/rolling/cooldown starts, and keep step velocity above slide but below roll in the movement override order. `Archer.get_animation_state()` uses presentation phase `STEP` with progress in `time` (no new payload key); replicas set `_step_direction` from the snapshot velocity. The frontier and arena share `playtest/sidestep_lab.tscn` for visual tuning.
- `scripts/damage_numbers.gd` is the shared scrolling `Label3D` presenter. Arena hosts spawn from real damage and clients spawn from the health delta in `apply_snapshot`; frontier enemies and the player use the same presenter. Do not add a damage-number network message.
- `Combat.stagger_from_damage(amount)` applies `0.08 + 0.012 × damage`, capped at **0.62 s**. It cancels movement intent, guard, draw, throw and swings. `Archer.set_hit_react(seconds)` presents a backbone/head recoil; the remaining react time rides in the animation snapshot as phase `STAGGER` with `time`, so replicas flinch without a new payload key. A weakly blocked dagger hit still applies half damage but **does not** stagger or drop the guard; the raised dagger absorbs the impact. Parries keep the fixed `PARRY_STAGGER` (0.8 s).
- `ArenaActor` buffers timestamped snapshots and interpolates between them (`interp_delay` 0.12 s remote, 0.05 s local client seat, 0.15 s maximum velocity extrapolation). Do not go back to an exponential `lerp` toward the newest position. Respawns/teleports snap and clear the buffer.
- Fighters use collision layer 4 but **mask only 1** (world). Actor-to-actor body collision is intentionally absent; `_separation_velocity` adds a bounded push only below 0.46 m centre distance so players can measure a stab without being shoved off aim. Blades and projectiles still query layer 4.
- `scripts/net_cache.gd` (autoload `NetCache`) persists the last player name, host address and UDP port in `user://net_cache.json`. The Hollow forms and the standalone arena lobby read it; successful host/join validation writes it. Keep script-mode tests on `user://net_cache_test.json`.
- `scripts/arena_world.gd` is a **64 × 64 m** field (`LIMIT = 32`) with the original centre trees/stone cover retained plus flank cover. `ArenaActor.bounds` is set from `World.LIMIT-0.3`; do not reintroduce the old ±21.7 clamp.

### Running slides

- C's new crouch intent during an achieved grounded sprint starts `RunningSlide` in both controllers. Require at least 6 m/s actual planar velocity, sprint input/stamina eligibility, and no existing crouch, cover or roll. Stationary Shift+C, walking and repeated true crouch intent must not manufacture or restart momentum.
- `try_start(body,stance,sprinting,rolling)` sets crouch intent; `step(delta,body,stance,direction,rolling)` precedes velocity selection, and `after_move(body,actual_velocity)` sees achieved post-collision movement. Keep `CoverMovement` as the sole capsule/camera stance owner. Slide velocity overrides ordinary acceleration only while active; roll remains the final override.
- The 0.75 s slide decelerates from 10.5 to 2.2 m/s, allows at most 36 degrees steering from entry, and persists without held movement/Shift. Continue normal sprint stamina drain; finish crouched. C cancels, successful jump/roll or cover attachment cancels, and floor loss/blocked forward movement ends it. Blocked headroom must not expand the capsule or cancel a rejected jump. Death/revive/camp and stale arena input clear sliding.
- Grounded combat remains available. `Archer.set_slide(progress,direction)` runs after `set_cover` and before the controller's pose updates; inactive progress is -1. The rig layers a fixed-length, asymmetric planted slide over authored crouch, suppresses stepping, and preserves upper-body weapon actions. Preserve heading through the exit blend rather than resetting it to world-forward.
- Animation snapshot `slide` is a compact `Vector4(progress,direction.x,direction.z,blend_weight)` so individual actor RPCs stay below ENet's MTU, including maximum-length UTF-8 names. Roll facing uses the existing replicated yaw, not a redundant direction field. Replicas apply physical cover before the animation snapshot. Clients still submit boolean crouch intent, never slide speed/position/pose claims.

### Cover and shoulder controls

- F toggles grounded, geometry-derived cover within 1.35 m. Both controllers use `CoverMovement`; WASD projects onto the contact tangent. Supported full-capsule sweeps follow slopes, curved/faceted offsets and contiguous collider seams without shape/RID identity locking. Genuine edges and hard corners still stop movement. Attached movement is 2.2 m/s, or 4.2 m/s with Shift and normal stamina/exhaustion, including crouch.
- RMB holds a manual top/left/right lookout. Side destinations try 0.45/0.55/0.65 m in order, requiring supported ground, a swept clear capsule and a finite-width forward firing corridor. Low-cover classification also checks deeper inward geometry so an inset rock face cannot invent a top peek. Keep one endpoint latched, and normalize signed lean against its selected extent. A blocked opposite-side request may retuck and resume sliding; a stationary blocked same-side request cannot jump to a longer endpoint. Use the same 2 cm protected-return tolerance as arrival, not a submillimetre latch that terrain recovery can keep locked. Bow attacks OR automatic exposure with manual input; melee bypasses this gate by exiting cover.
- A draw begun already exposed by RMB keeps manual ownership: releasing RMB retucks without canceling the held draw, including sliding away from the edge. Releasing that bow while tucked requests exposure again; blocked release cancels safely. A direct tucked bow draw owns exposure through RELEASE, then retucks unless RMB remains held. Stop, equipment changes, jump/roll, death/respawn and lost cover clear pending bow intent.
- X explicitly selects left/right lookout and smoothly swaps the camera, not weapon handedness. Capture horizontal view-right on cover entry, a new READY draw, manual RMB press or X. Preserve it through release/return and free look; do not recapture on mouse-up/Q-up. Both controllers feed `cover.view_right` before eligibility/step. Camera smoothing advances once per render frame; aim queries call `resolve()` without advancing it. Preserve swept-volume obstruction and overlap recovery.
- C toggles manual crouch while grounded and not rolling, with captured-cursor movement guards; achieved sprint-to-crouch starts the running slide described above. Armor remains equipment-button-only. Outside cover, ordinary crouch moves at 2.2 m/s and disables sprint. F exit preserves manual crouch. Standing checks headroom; never expand a capsule into an obstacle.
- Cover owns capsule height and smooth `crouch_amount` (0–1), even outside cover. Run `cover.step(delta,direction,peek,side,fast)` every physics tick; use its returned velocity only if cover was active before the call. World-space `lean` is UP times physical rise for low cover, or the signed tangent times physical lateral exposure at tall edges, including retuck. `set_cover(active,normal,crouch_amount,peeking,lean)` runs before locomotion/roll pose updates in both modes and replicas. Keep cover data in the single physical cover snapshot, not duplicated in `get_animation_state()`; apply it before `apply_animation_state()`. Camera height follows crouch outside cover too.
- The rig layers authored `Cover_Lean_Top/Left/Right` pelvis/spine/head deltas in the cover frame so aiming cannot reverse a lean. Facing blends from the protected outward stance toward the aim point with exposure, including idle peeks and retuck. Apply the layer before foot and weapon corrections; preserve sword grips and actual blade sweeps. Retuck must keep its protected anchor until the capsule returns, even with movement held.
- Authored `Crouch_Idle_Loop` / `Crouch_Fwd_Loop` replace the crouched stance/steps, using the JSON stride estimate and actual speed for cadence. Layer only the lower body during bow/sword actions and two-handed carry; preserve overall 0.58 m pelvis lowering and fixed-length planted legs. Side peeks stay crouched; blocked top peeks cannot expand the collider or invent exposure.
- Space caches grounded state before `prepare_jump()`; blocked standing headroom prevents takeoff. Otherwise it exits cover, clears manual crouch and peek latches, restores the standing collider and performs the existing jump/roll. Apply queued jump velocity even if stance preparation changed the floor cache. Death, respawn and camp return use `cover.reset()` and clear held intent.
- Arena validates boolean crouch intent and lookout context (`pressed`, horizontal unit `right`, ±1 `side`). The host derives all geometry, anchors, exposure and collider height. Reliable peek-context messages precede draw/release without fabricating RMB presses. Aim-bearing movement/action RPCs include the observed own-actor snapshot tick, validated against snapshots actually sent. Keep accepted aim and tick atomic: stale samples cannot overwrite newer aim, but valid stale reliable release intent is not dropped.
- Remote `Combat.cover_aim_ready` requires an aim acknowledging the current physical exposure epoch. Reset that epoch on retuck, side transition, exit and lifecycle reset. Keep charge frozen until fresh exposed-camera aim arrives, then run the normal shaft check. Host/local/bots and noncover release are unchanged. Existing input_age >0.65 handling cancels automatic/frozen cover intent; do not add retry timers or allow a delayed shot after input resumes.

### Bow charge and recovery

- `Archer.BOW_DATA.draw_seconds` is the complete time to full charge: small/medium/large currently take 1/2/3 seconds. Raising is included, not an extra delay before charge begins. Base launch speeds are **66/84/102 m/s** for the shortbow/recurve/longbow; partial charge scales speed from 45% to 100% alongside damage.
- `draw_amount` drives the bar, string tension, and damage fraction. Half the draw duration means half damage; for the longbow, 1.5 seconds gives 50% of its base damage.
- Preserve the action sequence: `READY` → `DRAWING` → `HOLDING` if fully charged → `RELEASE` → `RECOVER` → `READY`. Release is also valid during `DRAWING`; holding at full charge never auto-fires.
- In cover, an early bow release sets replicated `rig.charge_frozen`: charge stops at input release while the raise clock continues. `Combat` fires once only after physical exposure and the 0.30-second raise; waiting never increases damage. Non-cover release timing remains immediate.
- There is no separate bow cooldown or movement recovery penalty. Readiness follows the actual release/re-nock animation through `get_bow_recovery_progress()`. The current follow-through is 0.28 seconds and arrow retrieval/re-nocking is 0.95 seconds.
- Every shot, including zero/partial charge, spends the nocked arrow and completes recovery before another draw. Equipment swaps, cancellation, or rolling cannot skip/restart that recovery. Canceling an unreleased draw does not spend its arrow.
- Carry leftover frame time from release into recovery. Do not add a frame-dependent extra delay at phase boundaries.
- Aim remains a world-space point from the camera ray, not target tracking or gravity compensation. Start the query at the projected actor position plus `cover.camera_height()` and exclude the shooter and the attached cover body through `CoverMovement.attached_surface()` (host-cached, replica-derived from `normal`) so top peeks can fire over the wall you are posted against. Never choose the query start from the animated muzzle: it feeds bow facing/raise back into targeting, skips close crosshair targets and makes shoulder convergence unstable. Aim the bow from its cheek anchor. Before a cover release, sweep the actual nock-to-tip shaft with finite radius and an initial-overlap check. A fresh exposure gets `Combat.SHAFT_SETTLE_GRACE` (0.15 s) for its lean/bow pose to settle before a blocked shaft is treated as permanent; a settled obstruction still cancels pending release/frozen charge.
- A released arrow travels on the center crosshair ray, not a converging line from the bow tip. `Combat.set_camera_ray` validates a muzzle point on that ray (preferring the point nearest the rendered tip) with a spawn-overlap check, a clear path to the aim point, and a clear link back to the rendered tip; if any check fails, it clears the override and the arrow uses the rendered tip. The arena sends the client camera-ray origin with aim actions and movement, validates it within 12 m of the actor, and replicates the captured visual start in the shot event. `Arrow` blends its rendered shaft from that visual start to the authoritative path over `VISUAL_BLEND_SECONDS` (0.12 s) and snaps it to the impact point. Ordinary projectile collision alone applies damage. Never remove the fallback: a camera-ray spawn buried in posted cover must not shoot through it.

### Damage zones

- `scripts/hitbox.gd` owns the **2x head multiplier** and the zone profiles for humanoids, the wolf, the sentinel and the cinder devil. Head zones are logical damage volumes against the single physical body capsule; do not add extra collision shapes, layers, areas or RIDs. That keeps arrows, blades, movement and cover on the existing authoritative collision path.
- Zones are upright cylinders around animated joints: arena actors read the rig's `Head` bone, the wolf reads its imported `head` bone, the sentinel uses its stone head and the devil reads its animated procedural head. Crouch, cover lean, rolls and the wolf's bite move the zone with the skeleton.
- Arrow damage classifies the actual ray hit point with `Hitbox.is_headshot`. Blades must use `Hitbox.blade_headshot` with both swept blade segments and the blade radius; a shape query's rest point can sit anywhere in the overlap and must not decide the zone. A vertical greatsword cut legitimately crosses the head zone while a horizontal one-handed cut contacts the chest.
- Receivers take a `headshot` boolean: `ArenaActor.take_damage` / `receive_melee` and `enemy.gd.take_damage`. Apply the multiplier before armor and before the frontier damage label. Arena damage stays host-authoritative; do not add a headshot field to snapshots or trust client classification.
- `melee_roll_regression` intentionally expects the greatsword's vertical cut to deal 2x and the one-handed cuts to deal base damage. Do not flatten those expectations to a single value.

### Thrown weapons

- Hold **T** with a sword or dagger to charge; release to throw one copy. Melee stays on LMB, wheel up (stab) and wheel down (overhead). `Archer.begin_throw()` uses dedicated phases `T_DRAW` → `T_HOLD` → `T_RELEASE` → `T_RECOVER` so the charge never collides with bow phases or melee and the snapshot phase stays short. Keep the phase names in `Combat.advance`, `get_attack_interval`, `update_aim`, both HUDs, and the animation-state replica path.
- Charge time is the equipped weapon's `seconds` (1/2/3 s swords, 0.5 s dagger). Damage is `base damage × clamp(charge,0,1)` via `Combat.throw_damage`; the projectile uses `ThrownWeapon`, the arrow's gravity (-4), swept ray collision, head-zone multiplier, and stops on the first contact. It is not `receive_melee`, so guards never parry a throw.
- Spent throw timing is `Archer.RELEASE_SECONDS` + `Archer.RECOVER_SECONDS` (0.28 + 0.95). `Archer.get_recovery_progress()` covers both bow and throw phases. Throwing gates on `Combat.melee_progress >= 1`, like melee, because it uses the same weapon.
- Endless supply is deliberate until inventory is implemented: the equipped weapon never changes or disappears permanently. `_sync_weapon_visibility()` hides it only during `T_RELEASE` and restores it in recovery. Do not decrement inventory or mutate `sword_index`/dagger availability.
- Throw pose samples the existing authored melee clip (`_throw_clip_time`): the chamber through charge, the authored strike on release, and the follow-through as recovery. Do not invent a procedural throw or reuse bow arm IK. The greatsword carry/guard overlay is disabled during throw phases.
- Cover behavior mirrors the bow: `Combat.begin_throw`/`release_throw` use the shared exposure, frozen-charge, and `cover_aim_ready` gates. `_cover_throw_clear` sweeps the exposed hand down the aim line for 1.2 m; obstruction cancels instead of throwing through cover.
- Arena: clients send `"throw"` / `"throw_release"` (aim + observed snapshot tick) and the host validates them like draw/release. `ArenaActor.thrown_weapon` feeds `Arena._on_thrown_weapon`, which spawns the authoritative projectile and broadcasts `_throw_event` reliably. Replicas spawn visual-only projectiles with `authoritative_damage = false`.

### Swords, daggers and state isolation

- Horizontal cuts are forgiving for half-size targets: `_apply_horizontal_arm_path` lowers the cut plane toward the crosshair (70% blend, clamped 0.35 m to chest height) and biases the blade forward; `Combat._on_melee_sweep` extends right-hand horizontal tips by 0.14/0.18/0.22 m and adds 0.045 m radius; right-hand daggers and the left dual-wield dagger get a 0.38 m / 0.06 m envelope. Keep this scoped to horizontal cuts and daggers; overheads and sword stabs keep their real blade volumes, and no actor-centered fallback may replace the sweep.
- Swords use fixed-duration uncharged swings with three variants. `overhead` and `horizontal_left/right` use the weapon's 1/2/3 s duration and authored overhead weight transfer; horizontal variants add a hip-led yaw arc plus a crosshair-height lateral hand path with a forward blade bias so the blade genuinely cuts across; the hit volume gets a horizontal-swing reach/thickness envelope for short targets, and the greatsword support hand follows the hilt. `stab` uses the authored `Dagger_Stab` clip at **0.5 s** and solves the sword arm along the crosshair, like the dagger. `Archer.begin_melee(hand,variant)` stores the variant per swing; phase is `MELEE`/`MELEE_HL`/`MELEE_HR`/`MELEE_ST` for the right hand and `MELEE_L` for the left dagger. Replicas decode all of them. The dagger ignores the variant and keeps phase `MELEE`. Damage comes from continuous blade-volume sweeps during the authored striking interval, not an attacker-centered cone or a fixed timestamp. Each victim can be damaged once per swing; world contact blocks further damage through cover.
- The dagger is a separate `weapon == "dagger"` with one size. `Archer.DAGGER_DATA` owns 0.5 s / 14 damage / 1.2 m reach / 0.34 m blade; `_profile.clips.stab` (`Dagger_Stab`, 0.5 s, 10/60–17/60 strike window) is authored in `tools/prepare_character.py`. During a dagger MELEE the right arm is solved along the crosshair aim: the authored chamber/extension distance is projected onto the aim line and extended toward the point during the strike, and the socket is rotated so the blade itself points at the aim rather than the hand bone. The hips and feet keep the authored stance; there is no pelvis lunge, step or auto-target, so a high aim stabs high while a low aim angles the blade down. The aim solve is skipped for a placeholder/self aim within 0.35 m, and replicas derive the same pose from the replicated aim/phase/time. The blade sweep remains the only damage source. Do not turn the stab into a cone, reuse a sword overhead clip, or give the dagger a two-hand grip.
- A dagger guard is a **weak block**: it never parries, takes a hit at `WEAK_BLOCK_DAMAGE_SCALE` (50%), spends `DAGGER_BLOCK_STAMINA` (30), and does not neutralize or stagger the attacker. Swords keep the 0.25 s parry / full held block. Dagger-guard presentation reuses `Sword_Block_Loop_OneHand`. A dagger never participates in sword clashes.
- **Dual wield** (`weapon == "dual"`) is sword-right plus dagger-left. Each hand owns an independent elapsed time (`_left_melee_time` / `_right_melee_time`) and recovery clock. `Archer.begin_melee("left")` starts the dagger even while the right sword is active; `"right"` starts the sword during a left stab. The same hand cannot restart until its own clip completes. The primary body clip is the right sword whenever it is active, otherwise the left dagger; `phase` is `MELEE*` for a right-hand swing (`MELEE`, `MELEE_HL`, `MELEE_HR`, `MELEE_ST`) or `MELEE_L` for the left dagger. The left strike holds the offhand low guard through windup and extends the left arm along the crosshair through its contact window; the right arm is restored to neutral only when the right hand is not swinging. Outside a left strike the left arm keeps that fixed low forward guard so the dagger points with the character. The guard-to-thrust path keeps the left forearm clear of the skinned torso; do not reintroduce the mirrored authored chamber, which crosses the chest. `_sword_grip_left` is the X-mirror of the exported right grip (the skeleton's left side is an exact mirror).
- `melee_started(hand)` and `melee_sweep(hand,...)` carry the hand. `Combat` keeps a separate swing record and progress for each hand (`left_melee_progress`/`right_melee_progress`) and emits both hands' sweeps independently. The public `melee_progress` remains the single-weapon/right recovery and a display alias for dual. A standard block calls `abort_swing(hand)` so only the contacting hand resets; the other keeps its clock. A parry calls `stagger`, which cancels both hands. `abort_melee_to_neutral` clears both for clashes/cancellation.
- Replication keeps the per-actor snapshot below ENet's MTU without a new key: during `MELEE*`/`MELEE_L` the otherwise-idle animation `draw` field carries the non-primary hand's elapsed time (`-1` when idle), while `time` carries the primary. The right variant rides in `phase` (`MELEE`, `MELEE_HL`, `MELEE_HR`, `MELEE_ST`); replicas derive the right duration from the replicated weapon and variant, and the left is always `DAGGER_DATA.seconds`. Do not add a second melee vector to the snapshot; the maximum-name payload is already near the MTU.
- Dual wield **cannot guard**: `Combat.start_block`/`Archer.set_blocking` reject it and `can_equip_shield` is false. Instead, `Combat.resolve_melee_defense` returns `DEFENSE_PARRY` when `rig.weapon == "dual"`, `rig.in_strike_window()` is true for either hand, and the attacker is in front. The parry applies no damage or stamina cost, does not cancel the dual wielder's swing, and staggers the attacker through the existing `PARRY_STAGGER` path. Only dual wield has this attack parry; front facing and the authored strike window are both required.
- The shield (`scripts/shield.gd`) is an `AnimatableBody3D` on collision layer 8, built procedurally and hidden while stowed. Its local -Z is the face; `Archer._update_shield_pose()` carries it on the left hand when idle and raises it at the chest/head when `_blocking`, overriding only the left arm. Arrows include layer 8: a shield hit applies no damage (the collider has no `take_damage`), and the arrow reparents to the shield; an arrow into a player body damages and reparents to the player body (`ironwood_player` meta). The arrow keeps its shaft visible and times out with the existing age limit. The shield is not in the movement, aim, cover or melee masks.
- Arena shield state is packed into `ArmorData.SHIELD_BIT` (bit 10) of the snapshot `armor` field, above the two-bit-per-slot armor state, decoded by `apply_snapshot`, so the maximum-name snapshot stays below ENet's MTU. Clients send `"shield"` as a boolean; the host stops the guard and validates eligibility. Replicas raise the shield through the replicated `GUARD` phase and the decoded state; the shield collider exists on every peer.
- `Combat` snapshots the swing weapon, damage and duration at `melee_started`, so switching loadouts cannot change an in-flight hit or its recovery clock. Keep `get_blade_base/get_blade_tip`, `melee_radius`, and the shared sweep path weapon-aware.
- `Combat.melee_progress` is independent of bow readiness. Switching to a bow must neither block bow charging with sword recovery nor erase that recovery when switching back.
- `attack_progress` is presentation/replication state; do not treat it as a universal cooldown gate. `ArenaActor.revive()` resets both progress fields and rig/roll state.
- New attacks require solid ground and cannot start while rolling. Preserve cancellation before melee impact and the greatsword's two-hand grip.
- A valid `Combat.begin_melee()` immediately exits sticky cover and calls `rig.set_cover(false,...)` before the first swing pose. No peek/edge/headroom prerequisite, deferred melee, automatic retuck, teleport or forced stand. Preserve manual crouch and collider height; ordinary stance updates may stand only when clear. Failed cooldown/ground/weapon/roll gates leave attachment unchanged. Movement is free during the swing, and F is required to reattach even if RMB stays held. World blade collision still blocks damage through cover.
- `melee_started()` resets per-swing victim state. `melee_sweep(previous_base, previous_tip, current_base, current_tip, radius)` supplies chronological world-space blade samples from the same pose used for the visible weapon. Preserve source exclusion, authoritative-only damage, cancellation, and coarse-frame contact coverage.
- Arena melee resolves through `ArenaActor.receive_melee` rather than unconditional `take_damage`, so a front guard is timing-authoritative. Arrow damage stays on `take_damage`; do not let a held guard parry projectiles. A real blade contact while both sword users are inside `Archer.in_strike_window()` and mutually facing is a **clash**: no damage either way, both swings are cancelled to READY with recovery cleared, both bounce apart, and sparks/clang replicate. Never reorder this into two independent damage trades or add sword-to-sword contact geometry. Clash sets `clash_cooldown` only to stop bots from re-clashing in lockstep; human swings are not cooldown-gated.
- Held guards use dedicated character-only loops from `assets/characters/ironwood_ranger.glb`: `Sword_Block_Loop_OneHand` for short/arming swords and `Sword_Block_Loop` for the greatsword. Both are 120-sample / 1.983-second breathing loops authored by `tools/prepare_character.py` with planted feet; the two-hand clip solves the support palm onto the actual hilt. Never fall back to `Sword_Idle`/`Sword_Idle_OneHand` for blocking. The clips animate only the Ranger skeleton; the sword stays the runtime socketed weapon. When crouched or sliding, pass `_blocking` into the lower-body-only crouch/slide layer so those legs cannot overwrite the guard arms. `Sword_Block_Loop*` are validated at 240 Hz for forearm clearance, support-hilt error and runtime-blade path; the JSON's `block_authoring` records wrist/elbow/blade targets.
- Block state is host-authoritative in the arena. Clients send `{pressed, forward}` on RMB press/release; the host validates and applies `set_block`. Guard presentation rides in the animation snapshot's `phase` as `GUARD`, which replicas map back to gameplay `READY`; do not add a `blocking` or `block_time` snapshot field, because the maximum-name snapshot already sits at the MTU boundary. Guard timing stays host-only: replica HUDs show **GUARDING** without inventing a parry window. Input age >0.65, cursor release and focus loss stop the guard. The frontier routes `enemy.gd`'s `attacked(attacker, amount)` through `_on_enemy_attack`, so parries call `stagger(0.8)` on the wolf, sentinel or cinder devil instead of applying damage.

## Authored skeletal animation workflow

- The character is a textured, skinned Ranger with a 65-bone skeleton and authored clips. `assets/characters/LICENSE.txt` records the CC0 sources and modifications. Do not reintroduce the obsolete procedural body or a hand-position interpolation masquerading as a heavy sword animation.
- `tools/prepare_character.py` samples and retargets genuine source motion in Blender. The two-handed overhead is Gres's authored load/cut/recovery; the one-handed clip is a Quaternius overhead finisher with timing-only smoothing. Keep the original trajectory and anatomical elbow bend; bake proportion/cloth-clearance corrections offline instead of inventing runtime sword elbow poles.

Their asset-space directions and measured crouch stride are recorded in JSON; keep arm-local poses neutral for additive combat layering.
- Keep the GLB, JSON, provenance and `.glb.import` settings together. `nodes/use_name_suffixes=false` preserves names such as `Idle_Loop` and `Wolf_Idle_Loop`; otherwise Godot silently strips the suffix. Animation sampling is 60 Hz. Check the actual importer behavior before changing texture handling: the wolf uses `gltf/embedded_image_handling=2` so its coat stays embedded in the imported scene without an extracted duplicate PNG, while the Ranger import currently records 3.

The leather set is the existing imported outfit split by slot; mail/plate/cloth are new skinned meshes. Rebuild with `prepare_character.py`, then reimport the GLB and verify the 16 `Armor_*` nodes, 65-bone skins and zero unweighted vertices.
- The Ranger model faces +Z; `archer.gd` rotates it by PI for gameplay's -Z convention. The wolf imports facing -Z, so `wolf_visual.gd` applies no wrapper rotation. Use the exported `sword_grip`, `palms`, clip timings, `bow_anchor` and wolf JSON. Skeleton global poses are skeleton-relative, not world transforms. - `advance_animation(delta)` is the deterministic animation entry point, driven automatically by `_physics_process`. Tests that step it manually must call `set_physics_process(false)`, not `set_process(false)`. Active blade motion is sampled at steps no larger than 1/120 second; finish all crossed strike samples before changing MELEE to READY.
- Different sword durations retime windup and recovery while keeping a fast cutting stroke. Active source intervals come from the asset JSON, not a new arbitrary damage percentage.
- Pass post-collision **actual velocity** into `set_locomotion()` in both game modes. Integrate `_locomotion_phase` from speed; multiplying total elapsed time by current speed causes phase jumps during acceleration. Replicate the phase with the rest of the animation state.
- Keep fixed imported bone lengths and attached endpoints. `_solve_limb` rotates authored bone frames for bow aiming and terrain contact; it must not stretch limbs or invent twist bases. Equipment size does not rescale the humanoid.
- Cache and blend authored poses before applying crouch, foot placement, or weapon IK. Reusing an already-corrected pose as the next blend source accumulates crouch offsets during movement transitions and can sink the skeleton. Keep rotation-only rig/model nodes at unit scale by constructing their yaw basis directly; repeated Euler setters must not feed extracted floating-point scale back into aiming rotations.
- The imported Head joint is at the neck base, not the jaw. Bow contact uses the cheek-surface landmark exported by Blender. Draw with reachable push/pull targets; fetch the next arrow around the outside of the shoulder; hold the bow in front of the centreline for re-nocking. Straight hand interpolation across the waist/chest can hide the forearm inside the outfit even while joint-length tests pass.
- Both free arms move with authored locomotion. Bow aiming owns its hand targets; greatsword carry keeps the two-hand grip. Preserve terrain contact, authored roll articulation and landing transitions. Inspect the real mesh from multiple angles, not only bone coordinates.
- Keep the corrected two-hand guard animation playing on the upper body. Its support-elbow/clavicle tracks vary with breathing and recovery; replacing them with a frozen frame-zero arm pose against a separately animated torso reintroduces clipping. Keep the support palm on the actual handle while preserving the authored striking arm.

## Cross-mode change checklist

1. Change the shared rig/combat/roll behavior first, then migrate both controllers and their callsites.
2. For new animation state, update both rig serialization methods and review actor snapshots/replica application. The host owns combat and damage; clients submit input/aim, not charge or damage claims.
3. Update the Hollow HUD, both match HUDs, equipment hints, and the README when controls or timing change. Never leave labels describing a removed cooldown, gesture, or launch path.
4. When gear, capacities, prices or equipped-kit behavior changes, update `PlayerState`, `ArmorData`, the hub inspector/stock, both mode-start loadout paths, the network packed state, and `hub_regression` together. Armor is per slot; do not collapse it back to one set index.
5. Check weapon swaps, cancellation, airborne restrictions, respawn, and host/client behavior at the affected state boundaries.
6. For world-art changes, update `WorldStyle`/`TextureLibrary`/shaders, run `world_art_regression`, and inspect rendered frontier and arena captures. Keep terrain, route, spawn, waystone and arena cover geometry unchanged unless gameplay behavior is intentionally changing.

## Restart and delivery

Godot keeps loaded scripts in memory. When asked to restart, identify processes by executable path and project arguments, preserve their scene/network arguments, close only this repo's game instances gracefully, and relaunch them. Do not kill unrelated Godot editors/games or silently force-kill a nonresponsive process. Restarting clears session-only frontier progress and disconnects a running match; reconnect clients to a restarted host.

Observe startup rather than assuming it: the hub emits `IRONWOOD_HUB_READY`, the frontier emits `IRONWOOD_WORLD_READY`, hosts emit `ARENA_HOST_READY`, and joined clients emit `ARENA_CLIENT_READY`. Leave a user-requested game running; close temporary verification instances.

Report the exact behavior changed, exercised verification, and any remaining blocker. Update this skill when an intentional change supersedes one of its repo contracts; do not preserve obsolete aliases or old input paths just to match these notes.
