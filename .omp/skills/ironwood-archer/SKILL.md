is a spawn snapshot, use `controller.refresh_gear(merc_id)` for live gear;
`WarbandBody` targets layer 4 by default, scenes fighting mobs set
`combat.target_mask = 2`; `Environment.fog_mode` resets `fog_density`; a scene door
must never be bound while `GameFlow.active` is false in a test; an aim point is
bounded **from the body** by `Combat.aim_point_valid` (`AIM_REACH` 400 m), never by
its distance from the world origin - the absolute `length_squared() > 1000000.0`
once copied out of the arena refused every swing, draw, throw and guard past 1 km
of the 1,374 m lane, from any distance, on any body, while bots kept swinging
(`warband_swing_clock_regression.check_far_from_origin`).

Presentation traps found the hard way: `Environment.fog_mode` in Godot 4.7 resets
`fog_density` to 1.0, so `scripts/world/environment_kit.gd` writes the density
last (before that every exponential-fog style, the arena included, was a
white-out); and a shoulder camera behind a cover tree is pulled in by its own
occlusion ray, so a mode's spawn ring has to leave the boom room.

## Test budget (hard repository rule)

**No test run takes more than a couple of minutes. Target one to two.** This is
enforced, not aspirational: `tools/run_tests.py` kills any single test at
`TIMEOUT` 90 s, reports `OVER BUDGET`, and fails the whole run if `TOTAL_BUDGET`
180 s is exceeded. 60-120 s is the band and 120 s is the ceiling anywhere; 600 s
or 900 s is never acceptable. Only a release build would be an exception, and
this repository has none.

- Run suites in parallel — `python tools/run_tests.py` is the **warband** suite by
  default, one pool with an isolated `APPDATA` per process and the two ENet tests
  serially afterwards. Never run 30 Godot processes one after another.
- The frontier / arena / delve suites are a **sandbox harness for the shared rig
  and combat code**, not a shipping mode. They are not part of the default run:
  `--base` only when the change actually touches `archer.gd`, `combat.gd` or the
  shared input layer, and `--only <test,...>` to run just the two or three that
  cover it.
- While working: do not run the suite at all. Write the code, run the one test
  that owns the change, plus a smoke run of the changed surface. A tree-wide run
  belongs to the integration point, once.
- A test that needs longer than the ceiling is measuring something too big. Make
  it cheaper (park off-screen bodies, cut the body count, skip impossible frames)
  rather than raising the ceiling. `cover_movement_regression` is the only fixed
  240 Hz walker left, and it fits.
- Verification by hand follows the same rule: exercise the changed path once,
  read the result, stop. Never re-run a check that already passed.

## Restart and delivery

Godot keeps loaded scripts in memory. When asked to restart, identify processes by executable path and project arguments, preserve their scene/network arguments, close only this repo's game instances gracefully, and relaunch them. Do not kill unrelated Godot editors/games or silently force-kill a nonresponsive process. Restarting clears session-only frontier progress and disconnects a running match; reconnect clients to a restarted host.

Observe startup rather than assuming it: the title prints `IRONWOOD_MENU_READY`, the town/frontier prints `IRONWOOD_WORLD_READY`, hosts print `ARENA_HOST_READY`/`DELVE_HOST_READY`, and joined clients print `ARENA_CLIENT_READY`/`DELVE_NET_CLIENT`. Leave a user-requested game running; close temporary verification instances.

Report the exact behavior changed, exercised verification, and any remaining blocker. Update this skill when an intentional change supersedes one of its repo contracts; do not preserve obsolete aliases or old input paths just to match these notes.
