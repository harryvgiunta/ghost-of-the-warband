# Authoring, intake, and PBR

Read from [the asset skill](../SKILL.md). Paths in commands are repository-relative. New paths and numeric budgets explicitly called **proposed** are planning defaults, not existing tooling or measured output.

## 1. Intake and reproducible source

1. Inspect existing assets and [Ranger provenance](../../../../assets/characters/LICENSE.txt) before acquiring anything. For each new source record its exact author, asset title/version, original filename, primary download URL, retrieval date, SHA-256, license URL and bundled license text, selected components, and modifications. Keep model, texture, and motion licenses separate when their sources differ. CC0 on the Ranger does not license an unrelated wolf; a free download is not proof of redistribution rights.
2. Use `web_search` for discovery and `read` for known source/license URLs. Download through an available real browser or HTTP client; never invent an acquisition service, login, payment, generated texture, or successful download. Inspect archive contents before extraction and retain referenced glTF `.bin`/image dependencies. Reject unclear or incompatible distribution terms before shipping.
3. Stage large downloaded packs in ignored `.runtime` storage, with pinned URLs/hashes and extraction instructions in tracked provenance. Preserve every original local edit: either a tracked, fully reproducible Blender script plus pinned inputs, or a tracked authoritative `.blend` with packed images and editable texture/mask sources. A proposed location for new authoring sources is `assets/source/<asset-id>/`; create it only for a real asset assignment. If source is too large, use the repository's agreed durable storage approach, not an ignored-only copy. Do not silently add an LFS dependency.
4. A deterministic builder resets to a known scene, uses stable names/order, explicit units/frame rates and seeds, checks input presence/hashes, saves only its own outputs, and fails on missing inputs. Parse its own arguments after Blender's `--`. Set `random.seed(...)` or a local seeded generator for fur variation; store the seed, parameters and source-tool version. Byte-identical GLBs across Blender versions are not assumed; reproducible geometry/maps/animation and documented versions are the contract.

## 2. Blender preflight and real command choices

The documented local Blender is `C:\Program Files\Blender Foundation\Blender 5.1\blender.exe`. Confirm availability with a filesystem tool and version command before an asset build; discover alternatives if missing instead of assuming Blender is on PATH. Blender has no mounted MCP route here: author via Blender's UI or a real CLI Python script using `bpy`, `bmesh`, and `mathutils`. Do not use system Python to execute `import bpy`.

For the **existing Ranger only**, when the exact sources from its provenance are unpacked:

```powershell
$Blender = 'C:\Program Files\Blender Foundation\Blender 5.1\blender.exe'
& $Blender --version
& $Blender --background --python-exit-code 1 --python tools/prepare_character.py -- .runtime/character-source assets/characters/ironwood_ranger.glb
if ($LASTEXITCODE -ne 0) { throw 'Ranger preparation failed' }
```

This existing script overwrites the Ranger output, imports the named Standard packs/Gres source, and uses the humanoid clearance helper. Do not run it for unrelated assets or rename its output to pretend it creates a wolf.

For a new asset, **first implement** an asset-specific script or author and save a real `.blend`. `tools/prepare_wolf.py` exists for the shipped default wolf; it is not a generic creature generator and does not make a new species or variant. Only after a new asset's script and input contract exist, run Blender with `--background --python-exit-code 1 --python <actual-script> -- <its-documented-arguments>`. For interactive sources, a deterministic export script may load the actual saved file with `bpy.ops.wm.open_mainfile(filepath=...)`; use `bpy.ops.wm.save_as_mainfile(filepath=...)` for the authoritative source. Do not dump a large untested generator into a command and call that a finished production pipeline.

Before coding exporter options or bake operators, query the installed API: `bpy.ops.export_scene.gltf.get_rna_type().properties.keys()` and the corresponding bake operator properties. Check version-specific enum choices. Explicitly set active object, selection, object/edit/pose mode and view-layer context before context-sensitive `bpy.ops` calls. Prefer direct data APIs when practical: `bpy.data.meshes.new`, `mesh.from_pydata`, `mesh.update`, `bpy.data.objects.new`, collection linking, and `bmesh` for topology. Resetting the scene is safe only in the dedicated background authoring process, not the user's open unsaved scene.

## 3. Build geometry that survives the camera and deformation

1. **Measure and block out.** Work in meters: `scene.unit_settings.system = 'METRIC'`, `scale_length = 1.0`; unit display alone does not rescale imported vertices. Blender is Z-up, glTF/Godot Y-up. Record Blender forward and exported forward independently. The current Ranger faces +Z after export and needs a runtime PI yaw; do not copy that correction to a new asset without measuring. Game-facing direction is -Z. Place a ground-standing object's origin at its intended ground/contact anchor unless its actual integration requires another pivot.
2. **Establish silhouette.** Compare orthographic front/side and gameplay perspective against references at intended size. For a wolf, use the [creature skill](../../ironwood-creatures/SKILL.md): shoulder/ribcage/waist/pelvis, muzzle, erect ears, digitigrade legs, hocks, paws, and tail must read as canine, not a stretched sphere with four sticks. Sculpt/blockout primitives may be intermediate authoring geometry; the shipped main body must be a coherent production mesh, not a runtime primitive assembly.
3. **Finish topology.** Retopologize/remesh the blockout into a continuous connected skin with appropriate loops around articulating joints and face. Separate eyes, teeth and claws are reasonable. Joining intersecting primitives with Ctrl-J alone is not a continuous skin. Remove internal hidden faces, accidental loose pieces, zero-area triangles and nonmanifold defects where a closed surface is intended. Preserve deliberate eye/mouth openings. Recalculate consistent outward normals; avoid negative/mirrored object scales. Apply mesh object rotation/scale before skin binding, not blindly after animation exists.
4. **Control density.** Proposed initial targets: a small prop 500–5,000 triangles; a visible medium creature 8,000–20,000 triangles, one primary body material plus only necessary eye/mouth surfaces. These are adjustable goals, not repo facts or permission to degrade anatomy. Spend vertices on silhouette and deformation, not hidden surfaces or microfur. Keep source quads where useful; use a stable final triangulation for bake/export so shading matches. For a skinned asset, check the export strategy with the creature skill before applying modifiers that can invalidate binding.
5. **UV deliberately.** Mark seams beneath the belly, inside limbs, behind ears and along the least-visible tail edge. Unwrap via Edit Mode UV tools or `bpy.ops.uv.unwrap`; establish one explicit UV map (commonly `UVMap`) and pack islands with consistent texel density. Allocate face/paws adequate resolution. Use a checker to inspect stretching. Mirrored UVs are acceptable only where asymmetry and tangent-normal seams remain controlled; use unique UVs for asymmetric coat markings/bakes. Bake margin/dilation should survive mipmaps: proposed 8–16 pixels at 1024px, larger for bigger maps. Test low mips, not just full-resolution islands.
6. **Freeze the asset frame.** Record evaluated rest bounds, contact height, pivot, exported axes, triangle/vertex/surface counts, UV name, and transforms. For creatures hand the mesh to the peer skill for skinning, weights and animation; do not claim neutral-pose topology proves deformation quality.

## 4. Paint or bake portable PBR, not a lighting screenshot

Start with a UV-mapped 1024px texture set for a medium creature, increasing to 2048 only if screen size warrants it. These are proposed defaults. Standard glTF metallic/roughness materials are the portable baseline: a Principled BSDF with image textures feeding Base Color, Roughness, Metallic and a tangent Normal Map node. Procedural Blender noise, hair/particle systems, Geometry Nodes and arbitrary shader graphs do not become Godot fur automatically; bake the surface signals or implement a deliberately scoped Godot shader with its own validation.

| Map | Meaning / color space | Wiring / constraint |
| --- | --- | --- |
| Base color | Pigment only, sRGB | Image Color → Principled Base Color. No cast shadows, ambient gradients, specular shine or camera lighting painted into it. |
| Roughness | Scalar data, Non-Color | Image Color (or separated G) → Roughness. Fur is mostly rough; nose/eye response differs. |
| Metallic | Scalar data, Non-Color | Fur/skin/wood/stone are 0; true exposed metal can be 1. Dirt on metal is not metallic. |
| Tangent normal | RGB data, Non-Color | Image → Normal Map (Tangent Space) → Principled Normal. glTF uses +Y/OpenGL convention; invert green once only if a verified DirectX source requires it. Neutral approximately (0.5, 0.5, 1). |
| AO | Scalar data, Non-Color | Optional small-scale occlusion only, separate from base color. Do not bake broad ground/contact shadows into a moving animal. |
| ORM | R=occlusion, G=roughness, B=metallic, Non-Color | glTF metallicRoughness consumes G/B; occlusion is a separate material texture reference reading R. Channel packing alone does not wire AO. |
| Coat masks | Linear data, Non-Color | Named region masks; keep their semantic channels separate from ORM and document each channel. |

For Blender image datablocks use `image.colorspace_settings.name = 'sRGB'` for base color and `'Non-Color'` for scalar/normal/mask maps. Image pixel APIs use Blender's working representation; do not write display-encoded color values into a linear buffer and then apply a second gamma transform. Inspect the saved image and imported result. Use `image.pack()` for images needed by a packed source/GLB; save authoring images intentionally rather than relying on an unsaved image datablock.

### Concrete fur texture recipe

1. Paint broad **anatomical pigment regions** on UVs: darker dorsal saddle/ruff and tail tip; mid-gray flanks; lighter lower jaw, cheeks, chest, belly and inner legs; dark nose/lips/pads and legible eyes. Use subtle warm/cool variation rather than uniform grayscale. These pigment boundaries must remain recognizable when the light moves.
2. Preserve editable masks for at least dorsal, underside and face/limb markings. Proposed RGBA mask channels can be R=dorsal, G=underside, B=face/leg markings, A=fur-versus-bare-skin; document overlap precedence/normalization. Keep nose/eyes un-tinted. Store masks in tracked source even if the first runtime version uses only a baked gray atlas.
3. Add directional, multiscale fur strokes following growth: away from muzzle/eyes, down neck and flanks, along limbs, toward tail tip. Paint in 3D Texture Paint to cross seams, or bake a deliberately authored field from Blender. A seeded noise texture alone is not fur; combine long low-contrast clumps with finer broken strands and region-specific lengths. Keep fine contrast modest so mipmaps do not turn into glitter or static.
4. Create a restrained bump/high-detail source and bake tangent normals to the final UV mesh. Fur roughness should vary subtly with clumps; a proposed starting range is 0.75–0.95, with nose/eyes authored separately. Avoid metallic fur and overstrong normals that make the coat look like rock. Use limited silhouette tufts modeled into the skin before considering alpha cards; cards require tested cutout/shadows/overdraw and are not a default hair solution.
5. For requested black/gray/white variants, reuse geometry, rig, clips, UVs and masks. Blend **region palettes** while retaining saddle/underside patterns and dark anatomy; a single global albedo tint is not sufficient. White coat needs visible midtones, black coat needs readable detail, neither is clipped pure white/black. Implement only the requested variants now. Baked palette atlases or an explicit mask shader are valid; the latter is new implementation, not an existing feature.

### Baking procedure and API anchors

1. Save a copy of the authored high-detail source and final low mesh; align them and settle final low-mesh triangulation/normals first. Use Cycles (`scene.render.engine = 'CYCLES'`) for the supported bake workflow. Create a destination image and an Image Texture node in **every** low-mesh material, make that node active (`material.node_tree.nodes.active = node`), and ensure a valid UV layer. Do not connect the bake target into the source being baked.
2. For high-to-low baking select the source object(s), then the low mesh as active, enable `scene.render.bake.use_selected_to_active`, and use a measured cage/ray distance that reaches detail without crossing to another limb. For self-material baking disable selected-to-active. Use explicit image dimensions, output paths and margins.
3. Base color: bake diffuse color with only the COLOR pass, not DIRECT/INDIRECT lighting (`bpy.ops.object.bake(type='DIFFUSE', pass_filter={'COLOR'})` where supported). For a particular procedural scalar/mask, temporarily route that signal through Emission and bake `type='EMIT'`, then restore the original graph. This captures data without scene lighting. Bake normal with `type='NORMAL'`, `scene.render.bake.normal_space = 'TANGENT'`; bake AO separately only if needed.
4. Save each result, inspect seams/black patches/cage intersections, then pack ORM with R=AO (1 when absent), G=roughness, B=metallic (0 for fur). Do not resample a data map through sRGB. Verify exporter AO support using its installed documentation/node convention or omit optional AO; do not label an unconnected image as working AO. Verify the exported glTF material references, not only the Blender viewport.
5. Rebuild the final portable material from baked images and render with changed light directions. If highlights/shadows remain painted onto the coat, repair the bake. Deliver editable masks/source and the export material, not just a beauty image.
